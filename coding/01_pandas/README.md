**易错点**

1. `fillna(method="ffill")` 在 pandas 3.0 **已被移除**，改用 `.ffill()` / `.bfill()`
2. `dropna(add_indicator=True)`、`fillna(downcast=)` 同样已移除

4. 无脑 `df.dropna()` 会删掉 78% 的行（59/270）

| 难点 | 为什么是坑 | 讲解位置 |

| 知识点 | API | 出现位置 |
|---|---|---|
| 完全重复 vs 业务键重复 | `duplicated(subset=)` | 讲解 3.1 |
| `keep` 三态语义 | `first` / `last` / `False` | 讲解 3.2 |
| 哨兵码 vs 真极端值 | 业务规则判据 | 讲解 3.3 |
| 3σ 法 | `mean ± 3*std` | 讲解 3.4 |
| IQR 法（Tukey 围栏） | `quantile` + `1.5*IQR` | 讲解 3.4 |
| **分组异常检测** | `groupby().transform(iqr_mask)` | 讲解 3.5 |
| 处理策略 | `replace` / `clip` / `mask` / `where` | 讲解 3.6 |

**易错点**

1. `duplicated(keep=False).sum()` 当"要删的行数" → 结果是 2 倍
2. 只用完全重复口径 → 漏掉"业务重复"（`记录ID` 不同的那部分）
3. 只用业务键口径 → 会误删"业务键碰巧相同"的正常记录
4. **用 `clip` 处理哨兵码** → 假值被洗成"看起来正常"的值，污染被永久隐藏
5. 用 `mean ± 3σ` 却不清洗极端值 → `std` 被拉爆（区间宽 8110），失去筛选力
6. 全局 IQR 处理多峰数据 → 误杀 41 个正常高值（52 vs 10）
7. 有物理边界的字段（湿度）用统计法 → IQR 只抓到 1 个，业务规则抓到 5 个
8. `mask` 与 `where` 语义相反 → `mask` 命中即换，`where` 不满足即换
9. `drop_duplicates()` 忘了 `ignore_index=True` → 索引留窟窿
10. 处理完不复查、不画箱线图 → 按步骤给分，**画了/写了才算**

**难点索引**

| 难点 | 为什么是坑 | 讲解位置 |
|---|---|---|
| **用 `clip` 处理哨兵码** | 9999 被截断成"看起来正常"的值，污染被永久隐藏，比不处理更糟 | §3.6 难点深挖 |
| **多峰分布下的全局 IQR** | 负荷值按设备类型多峰（变压器中位数 521 vs 绝缘子 55），全局 IQR 判出 **52** 个"异常"，真哨兵只有 11 个 | §3.5 难点深挖 |
| `mean ± 3σ` 未先清洗 | `std` 被哨兵拉爆，围栏宽 **8110**（正常负荷才 5~590），反而漏掉全部 4 个 `-1` | §3.4 难点深挖 |
| 有物理边界的字段用统计法 | 湿度 IQR 只抓到 1 个越界值，业务规则 `[0,100]` 抓到全部 **5** 个 | §3.7 |
| `mask` 与 `where` 语义相反 | `mask` 命中即换，`where` 不满足即换（两者对 NaN 的处理还不同，见 ch07） | §3.6 |
| `duplicated` 两种口径 | 完全重复 **6** vs 业务键重复 **10**，选错要么漏删要么误删 | §3.1 |

**知识点表**

| 知识点 | API | 出现位置 |
|---|---|---|

| 按标签排序 | `sort_index(axis, ascending, level)` | 讲解 3.2 |
| 排序稳定性 | `kind="stable"` / `"mergesort"` / `"quicksort"` / `"heapsort"` | 讲解 3.3 |
| 名次 | `rank(method, ascending, pct, na_option)` | 讲解 3.6 / 3.7 |
| 组内名次 | `groupby(g)[col].rank(...)` | 讲解 3.8 |
| TopN | `nlargest` / `nsmallest` / `keep` | 讲解 3.9 |

| 多维频次 | `DataFrame.value_counts(subset=)` | 讲解 3.12 |
| 业务顺序排序 | `pd.CategoricalDtype(categories, ordered=True)` | 讲解 3.16 |

**易错点**

1. `sort_values` 默认 `kind="quicksort"` **不稳定**，并列行的先后不可复现
2. `na_position` 默认 `last`，且**不受 `ascending` 影响**（升序降序 NaN 都在末尾）
3. `ascending` 传列表时长度必须等于 `by`，否则 `ValueError`
4. 排序**不重置索引**，`loc[0]` 拿的不是第一名
5. `df.iloc[0, "列名"]` 报 `ValueError`——`iloc` 的列也必须是整数位置
6. `rank` 默认 `method="average"`，并列会给出 `2.5` 这样的半个名次
7. `rank` 默认 `ascending=True`，名次 1 是**最小**值
8. `rank` 默认 `na_option="keep"`，缺失行的名次仍是缺失（不参与百分位分母）
9. `nlargest` 跳过 NaN；`sort_values().head()` 靠 `na_position` 兜底
10. `nlargest(k, keep="all")` 可能返回 **> k 行**
11. `groupby().nlargest()` 返回多层索引，交付前必须 `reset_index`
12. `sample` 不写 `random_state` 不可复现
13. `sample(frac=很小值)` 会**静默返回空表**（行数按 `round(n*frac)`）
14. `sample(n=, frac=)` 同时给 → `ValueError`
15. `sample(frac>1)` 必须 `replace=True`
16. `sample(weights=)` 权重含负值 → `ValueError`（先 `clip(lower=0).fillna(0)`）
17. 加权 + 不放回还要求 `n × max(归一化权重) <= 1`
18. 加权抽样会显著拉高样本均值（5666.52 vs 379.68），不是 bug
19. `value_counts` 默认丢 NaN，要看缺失必须 `dropna=False`
20. `value_counts(normalize=True)` 的分母是**非缺失计数**
21. `value_counts(sort=False)` 是"首次出现顺序"，既非字典序也非稳定序
22. 字符串编号排序是字典序（`_10` 会排在 `_9` 前）
23. `时间戳` 读进来是字符串，务必 `pd.to_datetime` 后再排
24. `groupby(...).head(n)` 不加 `sort=False` 会按组名重排
25. `astype("category")` 按码位序设 `categories`，**不等于业务顺序**
26. 无序 `Categorical` 能排序（按 `categories` 顺序），但 `min()` / `max()` / `<` → `TypeError`
27. 中文按 Unicode 码位排 ≠ 业务序；`处理状态` 的码位序恰好与业务序相反

**难点索引**

| 难点 | 为什么是坑 | 讲解位置 |
|---|---|---|
| **`kind="quicksort"` 默认不稳定** | 并列行先后不可复现；实测 quicksort/heapsort 不稳定，mergesort/stable 稳定 | §3.3 难点深挖① |
| **排序后索引不重置 → `loc` / `iloc` 分叉** | `desc.iloc[0][VAL]` = **9999.0**，`desc.loc[0, VAL]` = **89.96**，两者都不报错 | §3.5 难点深挖② |
| **`rank` 默认 `method="average"`** | 五种 method 给五套名次：并列的 20 得 `2.5/2.0/3.0/2.0/2.0` | §3.7 难点深挖③ |
| **`sample(weights=)` 两道硬门槛** | 负权重报错；不放回要求 `n × max(p) <= 1`（本数据 `10 × 0.105759 > 1`） | §3.11 难点深挖④ |
| **`value_counts` 默认丢 NaN + 默认降序** | `备注` 的条目数 `2` vs `dropna=False` 的 `3`；`normalize` 分母只有 74 | §3.13 难点深挖⑤ |
| **`nlargest` 的 `keep` 与并列** | `nlargest(3)` 给 3 行，`keep="all"` 给 **4** 行；`nlargest` 索引顺序也与 `sort+head` 不同 | §3.9 |
| **`sample(frac)` 的静默空表** | `270 × 0.001 = 0.27 → round = 0`，返回空 DataFrame 不报错 | §3.10 |
| **`ordered Categorical` 指定业务顺序** | `处理状态` 码位序与业务序完全相反；`astype("category")` 改不了顺序 | §3.16 |

3. 1 个缺失值污染后续 `w-1` 个窗口结果（本例 23 个缺失 → **319** 个 `NaN`）
4. `rolling` 含当前行 → 造特征时就是标签泄漏，必须 `shift(1)` 打底
5. `gb.rolling()` 返回两级 `MultiIndex` → 直接赋回原表报 `TypeError`
6. 顺序错了但索引"看起来对" → 不报错、不 `NaN`，**静默错位**
7. `shift(-1)` 是取未来值
8. `ewm(span=24)` ≠ `ewm(alpha=0.24)`，换算关系是 `alpha = 2/(span+1)`
9. `ewm` 默认 `adjust=True`，流式场景要显式 `adjust=False`
10. `rolling("24h")` 在 `RangeIndex` 上直接 `ValueError`
11. 时间窗口的 `min_periods` 默认是 **1**（与固定窗口的 `window` 不同）
12. `center=True` 会用到当前行**之后**的值 → 平滑可以，做特征即泄漏
13. 全局阈值与滑动阈值是两种业务口径，本例相差 **139** / **52** 条

**难点索引**

| 难点 | 为什么是坑 | 讲解位置 |
|---|---|---|
| **`min_periods` 默认值静默制造 `NaN`** | 默认 = `window`；且 1 个缺失污染 23 个后续窗口，`NaN` 从 46 涨到 **319** | §3.4 难点深挖 |
| **`rolling` 含当前行 → 标签泄漏** | 离线指标虚高、上线崩，赛后无从复盘；正解 `shift(1).rolling(24)`，代价是 **320** 个 `NaN` | §3.5 难点深挖 |
| **`gb.rolling` 与 `gb.shift` 索引不同** | 前者两级 `MultiIndex`、后者原索引；回贴写法完全不同 | §3.6 难点深挖 |
| **顺序错但索引"正常"的静默错位** | 不报错、不 `NaN`，错位率 **99.96%**，只能靠抽样手算查出来 | §3.6 难点深挖 |
| **`ewm` 四个参数互相等价但数值不同** | `span=24` ≡ `alpha=2/25`；写成 `alpha=0.24` 权重错一个量级 | §3.7 难点深挖 |
| **全局阈值 vs 滑动阈值** | 全局 P95 漏掉 **139** 条局部尖峰、多报 **52** 条；(全局 107 / 滑动 194) | §3.9 难点深挖 |
| 时间窗口需 `DatetimeIndex` | 在 `RangeIndex` 上 `ValueError`；且 `min_periods` 默认值不同 | §3.8 |

| 难点 | 为什么是坑 | 讲解位置 |

| **脏键导致 0 匹配** | 形状、列数、dtype 全部正常，只有新列整列 `NaN`；空白/全角/大小写三种脏法形状都是 `(270, 17)` | §3.2 难点深挖 |

| **`suffixes` 不给键加后缀** | 同名列有的加、有的不加，列名规则不一致 → 按名字取列会取错 | §3.4 难点深挖 |

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 编码与 na_values | `encoding="gbk"` / 默认 na_values 不认 `—` | 阶段 0 |
| 字符串转数值 | `str.replace(regex=False)` + `to_numeric(errors="coerce")` | 阶段 1 |
| 混合日期解析 | 中文日期替换 + `to_datetime(format="mixed")` | 阶段 2 |
| 类别标准化 | `str.strip()` + `replace(映射表)`，8->3 / 10->6 | 阶段 3 |
| 去重两连击 | `drop_duplicates()` / `drop_duplicates(subset=BIZ_KEY)` | 阶段 4 |
| 哨兵与填充 | `mask` 置 NaN + `groupby.transform("median")` 回填 | 阶段 5 |

| 可视化交付 | bar / hist(频数对账) / line + BytesIO PNG 魔数 | 阶段 9 |

**易错点**

1. `read_csv` 不报错 ≠ 读对了：编码、占位符、BOM 都会安静出错。
2. `—` 不在默认 na_values 里，缺失对账不做就漏 7 个。
3. `to_numeric(errors="coerce")` 让脏值统一落水，比让程序炸掉更可控。
4. 哨兵先记账（`n_sent`）再置 NaN，否则填充基准被拉偏。
5. 组内回填必须 `transform`，`agg` 形状对不上。
6. merge 后必查 `isna().sum()`——23 行缺失不是 2，是「行数 × 台区数」口径。
7. `cut` 之后必查 NaN：清洗干净时分箱 NaN 必须为 0，它从坑变成验收信号。
8. 断言引用的记账变量（缺失数 / 越界数）必须在**变更前**计算。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| 缺失数对账 | 14 自动 + 7 漏网，数字对不上后面全崩 | 阶段 0 难点串联 |
| transform vs agg 填充 | 形状语义不同，agg 回填直接错位 | 阶段 5 难点串联 |
| left join 的安静 NaN | 不报错不警告，是 ch13 最大陷阱 | 阶段 6 难点串联 |
| cut 的 NaN 是验收信号 | 前置清洗的镜子 | 阶段 8 难点串联 |
