## 四、逐章要点

### ch01 数据划分与流水线

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 模型选择 10% | 划分方式选错 = 从源头泄漏 | `train_test_split` 三参数、三种 CV 选型 |
| 模型训练 40% | 流程分步给分 | `Pipeline` + `ColumnTransformer` 组装、`fit` / `score` |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 保留法划分 | `train_test_split(test_size, random_state, stratify)` | §3.1 |
| 折外验证 | `KFold` / `StratifiedKFold` / `TimeSeriesSplit` | §3.4 |
| 防泄漏封装 | `Pipeline` / `ColumnTransformer(remainder=...)` | §3.6 |
| 类别编码 | `OneHotEncoder(handle_unknown)` / `OrdinalEncoder` | §3.9 |

**易错点**

1. `train_test_split` 不给 `random_state` → 结果不可复现，评分表里"结果一致"直接丢分。
2. 不平衡数据不分层 → 训练/测试正例占比漂移（实测 0.225 vs 0.1667）。
3. **先全量 fit 缩放器再划分 = 数据泄漏**（不报错，指标虚高）。
4. 时序数据用 `KFold(shuffle=True)` = 用未来预测过去。
5. `ColumnTransformer` 默认 `remainder="drop"` → 忘写进 transformers 的列**静默消失**。
6. `OneHotEncoder` 默认 `handle_unknown="error"` → 测试集冒出新类别直接 `ValueError`。
7. `KFold` 与 `StratifiedKFold` 的折正例数可差 **14 个**（20 vs 34），指标不稳定多半是它。
8. `Pipeline` 里 `clf` 是最后一步，`named_steps["ct"]` 才能拿到预处理器。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| 数据泄漏 | 全量 fit 的均值/方差把测试集信息带进训练 | §3.3 难点深挖 |
| 三种 CV 选型 | 随机 / 分层 / 时序混用静默给出错结果 | §3.4 难点深挖 |
| `remainder` 静默丢列 | 不报错，特征悄悄变少 | §3.7 难点深挖 |
| 未知类别 | 训练/测试类别集合不一致 | §3.9 难点深挖 |

### ch02 特征工程

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 模型训练 40% | 预处理是流水线第一段，按步给分 | 三种 scaler、SimpleImputer、两种 encoder、PolynomialFeatures |
| 模型选择 10% | 预处理方式与模型类型匹配 | 线性 drop=first、树模型 Ordinal、min_frequency 治理低频 |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 缩放三口径 | `StandardScaler` / `MinMaxScaler` / `RobustScaler` | §3.1 |
| NaN 穿透 | scaler fit 不报错、transform 保留 NaN（72 个） | §3.2 难点深挖 |
| 测试段越界 | MinMax `>1` 共 3 个（1.0045 / 1.0180） | §3.3 难点深挖 |
| 缺失填充 | `SimpleImputer(strategy, add_indicator)` | §3.4 |
| 独热编码 | `OneHotEncoder(drop, min_frequency, handle_unknown)` | §3.5-3.6 |
| 未知类别 | `ignore` 只归零未知段；drop+ignore 1.9.1 不报错 | §3.7 难点深挖 |
| 特征升维 | `PolynomialFeatures(degree, include_bias, interaction_only)` | §3.8 难点深挖 |

**易错点**

1. scaler 对 NaN 视而不见（72 个原样穿透），填缺失是 imputer 的活。
2. MinMaxScaler 只保证训练段在 [0,1]，测试段可越界且不报警。
3. `RobustScaler.center_` == 各列中位数 == `SimpleImputer(median).statistics_`，可互证。
4. `add_indicator=True` 形状 5 → 7，缺失模式（MAR 结构）本身就是特征。
5. OneHot 类别顺序是码位序；`drop="first"` 后全 0 行 == 基准类。
6. `min_frequency` 只合并 1 个类别时维度不变（一换一）；0.2 直接把缺陷类型整列吞掉。
7. `drop="first"` + `handle_unknown="ignore"` 在 1.9.1 实测能跑，别背旧结论，但全 0 与基准类不可区分。
8. `OrdinalEncoder` 默认遇未知类别 `ValueError`，树模型须配 `unknown_value`。
9. `PolynomialFeatures` 拒绝 NaN，必须先填充（与 scaler 相反）。
10. 未缩放直接 poly：x0² 最大 697425.4；升维三步曲 impute → poly → scale。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| NaN 穿透 scaler | 不报错，问题推给下游模型 | §3.2 难点深挖 |
| MinMax 测试段越界 | 「[0,1]」只是训练段语义 | §3.3 难点深挖 |
| min_frequency 维度陷阱 | 一换一不变维；阈值过高整列失效 | §3.6 难点深挖 |
| drop+ignore 组合 | 旧教程说必报错，1.9.1 实测能跑 | §3.7 难点深挖 |
| poly 拒绝 NaN + 爆炸 | 与 scaler 行为相反；69 万量纲 | §3.8 难点深挖 |

### ch03 特征选择与降维

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 模型训练 40% | 特征处理按步给分 | 方差筛选、SelectKBest、RFE/RFECV、PCA |
| 模型选择 10% | 过滤/包裹/变换三路线选型 | 各路线适用场景与互相验证 |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 方差筛选 | `VarianceThreshold(threshold)` + 1.9 的 min(方差, ptp) 坑 | §3.1-3.2 |
| 过滤法主力 | `SelectKBest(f_classif/chi2/mutual_info, k)` | §3.3-3.4 |
| 包裹法 | `RFE` / `RFECV(cv, scoring)` | §3.5 |
| 方差降维 | `PCA(n_components)` + 先 scale | §3.6 难点深挖 |
| 可视化降维 | `TSNE(init="pca")`，不可 transform | §3.7 难点深挖 |

**易错点**

1. 方差阈值看不懂量纲：threshold=100 只是「负荷值说了算」。
2. 标准化后方差全 1，`VarianceThreshold` 彻底失效。
3. sklearn 1.9 的 `threshold=0` 把 `variances_` 改写成 min(方差, ptp)，不是真方差。
4. `chi2` 要求非负：标准化/中心化后的数据直接 `ValueError`。
5. `mutual_info_classif` 不固定 `random_state` 结果不可复现。
6. 三种过滤法选中集互不相同——选型本身就是答案的一部分。
7. `SelectKBest` 传 DataFrame 才有可读的 `get_feature_names_out()`。
8. `RFE.ranking_` 里 1 是保留，其余数字是淘汰轮次。
9. RFECV 的结论可以反直觉：本数据 5 个特征全要，删谁降谁。
10. PCA 前必须标准化，否则第一主成分被大量纲绑架（98.22%）。
11. t-SNE 没有 `transform`、不可复现、只做可视化。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| 方差阈值的量纲陷阱 | threshold=100 只是「负荷值说了算」 | §3.2 难点深挖 |
| `threshold=0` 的 variances_ 不是方差 | 1.9 改写为 min(方差, ptp) | §3.2 难点深挖 |
| 三种评分三种口味 | chi2 非负约束；MI 捕捉非线性 | §3.4 难点深挖 |
| PCA 不 scale 被绑架 | 第一主成分吃掉 98.22% | §3.6 难点深挖 |
| t-SNE 三条纪律 | 无 transform、不可复现、不进 Pipeline | §3.7 难点深挖 |

### ch04 回归模型

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 模型训练 40% | 六族模型 fit/predict 按步给分 | Linear / Ridge / Lasso / DT / RF / GBDT |
| 模型性能评估 10% | 指标选型与解读 | R² / RMSE / MAE、负 R²、系数与重要性解读 |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 线性基线 | `LinearRegression` + 两种尺度的 R²/系数对照 | §3.1 |
| 系数解读 | 标准化后才能比大小（0.39 vs 113.06） | §3.2 难点深挖 |
| L2 vs L1 | `Ridge(alpha)` 收缩 / `Lasso(alpha)` 归零 | §3.3 |
| Lasso 尺度敏感性 | 换尺度归零决策不同（6/9 vs 7/9） | §3.4 难点深挖 |
| 背表与剪枝 | `max_depth`；640 行切 640 叶 | §3.5 |
| 集成上限 | RF 0.9529 / GBR 0.9627 + `feature_importances_` | §3.6 |
| 评估陷阱 | 负 R²（-0.0123）；RMSE 平方放大离群 | §3.7 难点深挖 |

**易错点**

1. 线性回归的 R² 对缩放不变——它验证不了系数是否可解读。
2. 原始系数排重要性是经典翻车点：容量 0.39 vs 标准化后 113.06。
3. Ridge 只收缩不归零；想用正则化做特征选择用 Lasso。
4. Lasso 的 alpha 只在固定尺度里有意义：换尺度必须重调。
5. Lasso 之前必标准化，否则归零决策（特征选择）跟着尺度走。
6. 全深决策树把训练段背下来（640 叶、train R²=1.0），max_depth 要显式给。
7. 树不吃 scale：对树做标准化不改变预测，纯属白干（但无害）。
8. RF 的 `feature_importances_` 是模型视角，与相关性/线性系数视角可能不一致（户数 vs 容量）。
9. R² 可以为负（本数据 −0.0123）：比猜均值还差 = 有 bug 先查 bug。
10. RMSE 对离群残差平方放大（44.73 vs MAE 20.80），报告两个都给。
11. ID 列别进特征矩阵：本数据测试段无新台区是运气，新台区一来独热全 0。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| 系数必须标准化后再比 | 未 scale 的系数差 290 倍，答辩翻车点 | §3.2 难点深挖 |
| Lasso 尺度敏感性 | alpha 的语义随尺度漂移，归零决策不可信 | §3.4 难点深挖 |
| 全深树背表 | train R²=1.0 是过拟合信号不是好成绩 | §3.5 |
| 负 R² 与 RMSE 放大 | 两个评估直觉都靠不住 | §3.7 难点深挖 |
| ID 列陷阱 | 新类别一来独热全 0，模型瞎猜 | §3.7 |

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 概率与分数的关系 | `predict_proba` / `decision_function` == logit(p) | §3.1 |
| 准确率幻觉 | `DummyClassifier(most_frequent)` 打平 0.7833 | §3.2 难点深挖 |
| 阈值移动 | `roc_curve` 39 阈值、Youden J=0.2455 | §3.3 |
| 训练端调权重 | `class_weight="balanced"`：FN 21→5 | §3.4 |
| 量纲敏感 vs 免疫 | KNN 敏感（raw 0.80 更准）/ GNB 免疫（逐位一致） | §3.5-3.6 难点深挖 |
| SVM 概率陷阱 | `LinearSVC` 无 `predict_proba`；`SVC(probability=True)` 走内部 CV | §3.7 |
| 背表与剪枝 | 全深 95 叶 train=1.0 → d5 18 叶 0.7917 冠军 | §3.8 |
| 排序能力 | AUC：LR 0.7946 反超 RF 0.6991 / GB 0.6809 | §3.9 |

**易错点**

1. 不平衡任务先看混淆矩阵和 F1/AUC，准确率只配做参考（21% 正例上 0.7833 = 什么都没学）。
2. `predict` 默认 0.5 一刀切；漏检严重先降阈值或加 class_weight，别急着换模型。
3. `roc_curve` 首阈值在 sklearn 1.9 是 **inf**，不是 1.0——旧教程代码直接 `thr[0]` 对账会懵。
4. 阈值移动（预测端）与 class_weight（训练端）效果相似原理不同，别混为一谈。
5. KNN/SVM 必须 scale；但 scale 不保证更准（KNN raw 0.8000 > scaled 0.7500），它保证的是**可控可解释**。
6. GaussianNB 不需要标准化，预测对逐列仿射缩放逐位不变——别画蛇添足还以为做了优化。
7. `LinearSVC` 没有 `predict_proba`；要概率用 `SVC(probability=True)`（内部 CV，慢且有噪声）。
8. `SVC` raw 输入会全预测负类（P=R=0）还不报错——比报错更危险。
9. 全深树 train acc=1.0 是背表不是好成绩；分类树同样要 `max_depth` / 剪枝。
10. 准确率冠军（d5 单树 0.7917）≠ 排序冠军（LR AUC 0.7946）；选模型先想清楚业务要标签还是分数。
11. RF/GB 的 acc 不一定高于调好深度的单树——「集成更强」要有前提。

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| 准确率幻觉 | 哑模型与逻辑回归打平 0.7833 | §3.2 难点深挖 |

| 量纲敏感的分界线 | KNN/SVM 敏感、树系免疫、GNB 仿射不变 | §3.5-3.6 难点深挖 |

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 无监督建模 | KMeans / 层次 / DBSCAN / GMM 的 fit-predict | 簇分配、簇心、新样本归属 |
| 聚类评估 | 无标签 + 有标签两类指标 | inertia / 轮廓系数 / ARI |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 完美聚类基线 | `KMeans(n_clusters=3, n_init=10)` ARI=1.0 | §3.1 |
| 量纲陷阱 | raw ARI 0.2557 vs scaled 1.0 | §3.2 难点深挖 |
| k 选择 | 肘部失灵、轮廓系数 k=3 出峰 0.5628 | §3.3 |
| 簇健康度 | `silhouette_samples` 各簇 0.54/0.59/0.56 | §3.4 |
| 编号任意性 | ward ARI=1.0 但与 KMeans 一致率 0.0 | §3.5 难点深挖 |
| eps 敏感性 | 0.3→289 噪声 / 0.5→9 簇 / 1.2→完美 | §3.6 |
| k-距离图 | p95=0.8173 → eps 拐点 ≈ 1.0~1.2 | §3.7 |
| 软分配 | `GaussianMixture.predict_proba` 行和 1 | §3.8 |

**易错点**

1. 聚类全家桶（KMeans/层次/DBSCAN/GMM）都吃欧氏距离，**一律先 scale**。
2. inertia 是量纲的奴隶：raw 的 2398 万和 scaled 的 402.6 不可比。
3. 肘部法经常看不出拐点——inertia 单调下降，肘「找不出来」是常态，配轮廓系数。
4. **簇编号没有语义**：跨算法/跨种子比较聚类用 ARI，别直接比标签。
5. `AgglomerativeClustering` 没有 `predict`：层次聚类不能给新样本发簇号，要服务化换 KMeans/GMM。
6. DBSCAN 的 `-1` 是噪声不是第 4 个簇：统计簇数时先把它剔掉。
7. eps 从 0.3 到 1.2 结果天差地别——k-距离图找拐点，别拍脑袋。
8. `KMeans` 在 1.9 的 `n_init` 默认是 `"auto"`（k-means++ 时为 1）——要复现请显式 `n_init=10`。
9. GMM 的概率是软分配不是置信度保证，边界样本 0.6/0.3/0.1 也是一种有效答案。
10. 有真标签时 ARI 才能算；纯无监督场景只能报轮廓系数 + 业务解读。

### ch07 分类评估

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 模型性能评估 10% | 指标选型 + 多分类 average 语义 | 混淆矩阵 / P / R / F1 / report / log_loss / AUC / PR |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 多分类基线 | RF 5 分类 acc 0.2667 vs 瞎猜 0.25 | §3.1 |
| average 三兄弟 | micro==acc；macro<weighted（少数类拖累） | §3.2 难点深挖 |
| report 机器可读 | `classification_report(output_dict=True)` | §3.3 |
| 混淆矩阵对账 | crosstab 行=support、对角线和=acc×N | §3.4 |
| 概率质量 | log_loss（过冲惩罚）/ Brier | §3.5 |
| 两条曲线的瞎猜线 | ROC=0.5 vs PR=正例先验 | §3.6 难点深挖 |
| PR 曲线结构 | len(prec)=len(thr)+1；末点 (1,0) | §3.7 |
| 综合指标 | fbeta / balanced_accuracy / MCC / kappa | §3.8 |

**易错点**

1. `average="micro"` 的 P/R/F1 恒等于 accuracy——报 micro 指标没加分。
2. macro 与 weighted 的差 = 类别不平衡的严重度；答辩时两个都报。
3. `average=None` 返回**按 `classes_` 字典序**的逐类数组，不是业务顺序。
4. `log_loss` 传**概率**不是标签；RF 概率过冲，AUC 不差但 log_loss 更差。
5. 全 0.5 的 log_loss = ln2 = 0.6931，这是「概率瞎猜」的对照线。
6. PR-AUC 的瞎猜线是**正例先验**（0.2167），不是 0.5；拿 0.5 当基准会高估。
7. `precision_recall_curve` 的阈值数组比分数短 1（末点无阈值）；f1s 直接 argmax 会踩 NaN，用 `nanargmax` 并丢末点。
8. `fbeta_score` 的 beta=2 重 recall（漏检贵）、beta=0.5 重 precision（误报贵）；方向别背反。
9. MCC/kappa 在不平衡下比 acc 诚实；kappa=0 表示与瞎猜一致。
10. 混淆矩阵用 `crosstab(真实, 预测)` 时行=真实类：support 对得上 report，别转置了还对账。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| average 语义 | micro 恒等 acc、macro 被少数类绑架 | §3.2 难点深挖 |
| 两条瞎猜线 | ROC 0.5 vs PR 先验，基准搞错全盘误读 | §3.6 难点深挖 |
| 概率校准 | RF 投票概率过冲，AUC 与 log_loss 背离 | §3.5 |
| PR 曲线末点与长度 | +1 结构与 NaN 陷阱 | §3.7 |

### ch08 回归评估

**考点表**

| 竞赛评分点 | 分值含义 | 本节覆盖 |
|---|---|---|
| 模型性能评估 10% | 指标选型 + 残差分析 | MAE/RMSE/MAPE/R²/median_AE/max_error/CV neg 指标 |

**知识点表**

| 知识点 | API / 参数 | 出现位置 |
|---|---|---|
| 基线先行 | 训练段均值预测：MAE 139.85 / R² -0.0123 | §3.1 |
| R² 解剖 | 1 - SSE/SST 手工复算 0.923381 | §3.2 |
| R² 三种极端 | 取负 -21.0964 / 测试均值 0.0 / 训练均值 -0.0123 | §3.3 难点深挖 |
| MAPE 双面性 | 单位不变 vs 小分母爆炸（合成 0.4 vs MAE 7.0） | §3.4 难点深挖 |
| 残差凭证 | mean 3.0419 / std 48.2273 | §3.5 |
| 大误差定位 | p90=79.08，大误差样本均值 367.69≈全体——结构性 | §3.6 |
| 右偏信号 | median_AE 28.37 < MAE 37.63 + max_error | §3.7 |
| neg 前缀 | negRMSE 五折全负，报成绩先取负 | §3.8 难点深挖 |

**易错点**

1. 不报基线直接报 R²=0.92 没有参照系；先给「训练段均值」这张底牌。
2. R² 的 0 点是**测试集**均值，不是训练集；分布漂移让常数预测也变负。
3. R² 没有下限，负得离谱先查方向/预处理 bug，不是模型差。
4. 跨数据集直接横比 R² 是无意义的——SST 不同，尺度不同。
5. MAPE 分母是真实值：低谷/接近零量测场景 MAPE 会爆炸，MAE 不会。
6. 残差均值≈0 只是必要条件；结构性偏差要看 p90 定位与残差~预测相关。
7. median_AE < MAE = 误差右偏（少数大离群）；两个都报。
8. `cross_val_score(scoring="neg_root_mean_squared_error")` 结果**恒为负**，报成绩先取负。
9. max_error 是单点最差，不是平均水平；用来兜底「最坏情况」而不是替代 RMSE。
10. RMSE=sqrt(MSE) 恒 >= MAE（柯西不等式）；差距越大离群越重，本身就是诊断信息。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| R² 无下限与 0 点定义 | -21.1 的方向错误 vs 0.0 的精确定义 | §3.3 难点深挖 |
| MAPE 小分母爆炸 | 一行 y=1 拽爆整体，MAE 镇定 | §3.4 难点深挖 |
| 误差结构性 vs 极值性 | 大误差样本的 y 并不极端（367.7≈373.7） | §3.6 |
| negRMSE 符号口误 | 把 -45 当 RMSE 报出去，评委必抓 | §3.8 难点深挖 |

**自检问题**

1. 为什么「常数=训练段均值」的 R² 是负的，而「常数=测试集均值」精确为 0？
2. MAPE 与 MAE 在什么数据形态下会给出相反的模型排序？
3. median_AE 比 MAE 小很多说明什么？报告里该怎么补？
4. negRMSE 取负后的五折波动（±3）说明模型稳定性如何？

7. RandomizedSearchCV 的 `uniform(a, b)` 是 [a, a+b)，第二个参数是「宽度」不是上界。
8. 换 scoring 全盘翻盘：AUC 冠军 ≠ f1 冠军（RF f1 只有 0.296）。
9. `best_estimator_` 已在全量数据 refit——直接拿去 predict 是对的，别再自己 fit。
10. 贝叶斯优化（Optuna）思想 = 用历史结果指导采样；两阶段网格是其手动版，竞赛足够。
