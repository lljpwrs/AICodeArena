**真值备忘（opencv 5.0.0，classic/ 素材）**

| 项 | 真值 |
|---|---|
| `camera.png` | `(512,512,3)` uint8、786,432 bytes；三通道完全相同（灰度存 PNG） |
| `home.jpg` | `(384,512,3)`、589,824 bytes；首像素 cv2 `[164,102,31]` / PIL `[31,102,164]` |
| 通道均值 B/G/R | 141.2399 / 123.8721 / 91.6084 |
| 灰度（cvtColor） | 均值 116.195，min/max 0/252 |
| 手写加权 vs cvtColor | 最大差 **0**（完全等价） |
| 三通道平均 vs cvtColor | 最大差 **20.3333**，平均差 9.8214 |
| float 均值截断 vs cvtColor | 不同像素 **195,079** / 196,608（99.2%） |
| 截断 vs 四舍五入 | 不同像素 **65,393** |
| 归一化回写 | float32 往返 **0 差异**；内存 2,359,296 bytes（4 倍） |
| resize 128 平均差 | LINEAR-AREA **4.2628**；NEAREST-AREA **8.8559** |
| `+100` 回绕 | 212,145 == 原值 >155 的通道值数；`cv2.add` 饱和到 255 计 215,325 |
| `-100` 回绕 / 饱和 | 回绕变亮 224,627 == 原值 <100 数；`cv2.subtract` 到 0 计 228,327 |
| gamma=0.5 | 均值 118.9068 → **165.7185**，无任何像素被压暗 |
| ROI[100:200,200:300] | 均值 103.233（全图 118.9068）；掩码内灰度均值 93.2983 |
| 直方图 | sum = 196,608 = 像素数；峰值 bin 111 计数 3,908 |
| 落盘往返 | PNG 0 差异 / 316,930 bytes；JPEG q90 424,160 差异、最大差 46、53,807 bytes；q50 494,055 差异、最大差 98、19,634 bytes |

**易错点**

1. **cv2 是 BGR**：`img[..., ::-1]` 是 BGR↔RGB 通用写法，不翻通道人脸变阿凡达。
2. `imread` 失败**返回 None 不抛异常**，后续 `.shape` 才炸，报错位置离现场很远。
3. 灰度图存成 PNG 读回来仍是 3 通道且三通道相同——拿它做通道分析会一无所获。
4. 灰度权重是 **0.299R + 0.587G + 0.114B**（R 在前，G 权重最大）；三通道平均是另一把尺子。
5. float 运算后回写 `astype(np.uint8)` 是**截断**：均值法截断与四舍五入差 65,393 个像素。
6. `resize` 参数顺序是 `(宽, 高)`，与 `shape=(H, W)` 相反。
7. 缩小用 `INTER_AREA`；`NEAREST` 缩小时与 AREA 平均差 8.86，边缘锯齿。
8. `uint8` 加减是**模 256**：回绕数恰好等于越界像素数（212,145 = 原值 >155 的个数）。
9. ROI 切片是**视图**：`roi[:] = 0` 会连带改原图，隔离要 `.copy()`。
10. `calcHist` 通道参数写列表 `[0]`；计数总和 ≡ 像素数是自检公式。
11. 掩码/标签图必须 PNG（JPEG q90 就丢了 75% 的通道值）。

**真值备忘（opencv 5.0.0）**

| 项 | 真值 |
|---|---|
| 坏图体检 | 假 JPEG / 0 字节 PNG → `None`；8×8 std 8.1650；64×64 纯色 std **0.0** |
| classic 尺寸分布 | 高 172~660、宽 324~868；最小 std = `moon.png` **13.33** |
| flip / rotate90 | `mean` 不变（增强集均值极差 **0.0**）；`rotate90` 293×440 → **440×293**；转 4 次回原 |
| 旋转黑角 | 原地 45° 黑占比 **0.2179**；扩边 (518,518) 黑占比 **0.5163**（≈1−128920/268324） |
| 缩放 / 平移 | 0.5 倍 → (146,220,3) 均值 115.8945→116.023；平移(20,10) 黑占比 0.078 |
| 亮度对比度 | `beta=+50` 均值 118.9068→**168.663**、饱和通道占比 **0.0358**；`alpha=1.5` std 58.9911→**79.854** |
| gamma=0.5 | 均值 → **165.7185**（提升 46.8117），**0 个像素被压暗** |
| 高斯噪声 σ=20 | 均值 118.8005、std **61.5029**；与原图逐通道平均差 15.5765 |
| 椒盐 5% | 盐 **4880** / 椒 **4947**；受影响通道值 **29426**（< 3×9827=29481，差 55） |
| 滤波对账 | 椒盐→中值 **6.0301** < 高斯→高斯 **8.0414** < 高斯→中值 8.7095（平均绝对差） |
| 直方图均衡 | std 45.5873 → `equalizeHist` **73.3206** / `CLAHE` **52.9708** |
| bbox hflip | `[47,186,66,199]` → **`[374,186,393,199]`**（W=440）；vflip → `[47,94,66,107]`（H=293） |
| bbox 旋转 45° | 外接框面积 247 → 512，**膨胀比 2.0729** |
| bbox 裁剪 | `[100:200, 50:150]` 后 6 框只剩 **2** 个有效（原出界 5 个） |
| patch 硬核对 | 框内 (13,19) patch 镜像后与翻转图对应 patch **完全一致** |

**易错点**

1. 坏图**不会报错**：`imread` 给回 8×8 或纯色图照样成功，必须靠体检发现。
2. 翻转/旋转只搬家不改值——`mean`/`std` 完全不变，别拿它当「数据变多了」的证据。
3. `rotate90` 会把 **H、W 互换**，之后任何按 shape 取参的代码都要跟着改。
4. **扩边后黑占比反而更高**（0.2179 → 0.5163）：扩边解决「内容被切」，不解决「有黑角」。
5. 加 `beta` 会**不可逆地削平亮部**（3.58% 通道顶到 255），gamma 才是安全提亮。
6. gamma 回写前必须 `np.clip`，否则 float→uint8 回绕打黑点。
7. 椒盐的受影响值恒 **≤** `3×(盐+椒)`——本图少 55，因为部分像素原本就是 0/255。
8. 增强必须**固定 seed**，否则两次实验的增强集不同，调参结论直接失效。
9. 滤波要跟噪声配对：中值治椒盐、高斯治高斯，配错反而更糊（8.71 最差）。
10. `equalizeHist` 全局一套映射，容易过曝；低照度增强优先 `CLAHE`。
11. **增强不同步标注 = 埋雷**：图翻了框没翻，模型学的是「帽子在右边」。

1. **`filter2D` 是相关不是卷积**：非对称核务必确认口径（差 352）。
2. **核和 ≠ 1 就改亮度**：未归一化均值核（sum=25）直接把图推到 255。
3. `blur` 与 `filter2D(均值核)` 等价，别以为两套 API 结果不同。
4. sigma 越大核越平（sigma=1 中心 0.4026 → sigma=5 只有 0.2080），平滑更强但更糊。
5. `sigma=0` 会让 OpenCV 按 ksize 反推（ksize=5 → 二项式系数），不是「无平滑」。
6. **1D 外积 = 2D 高斯**，所以能拆两趟；这是 `sepFilter2D` 的意义（961 → 62）。
7. 边界模式只影响最外 k 圈，但对贴边目标影响大；`CONSTANT` 补 0 的最大差可达 112.2。
8. **半径 1 时 `REFLECT` == `REPLICATE`**；要区分必须用半径 ≥2 的核或 `REFLECT_101`。
9. `BORDER_WRAP` / `BORDER_TRANSPARENT` **不被 `filter2D` 支持**，只能 `copyMakeBorder`。
10. **`std` 会骗人**：均值滤波 std 最低但对椒盐 gap 最大（9.2347）。
11. **低噪声密度下不滤波更接近真值**：2% 椒盐 gap 5.0841 < 中值 5.8994。
12. 核 `sum=0` 的滤波器（拉普拉斯）**对平坦区不响应**——这正是边缘检测的原理。
13. 方向性滤波必须 float32；uint8 会把 −202 截成 0（梯度总量只剩一半）。

1. **Sobel 不写 `ddepth` 就是废的**：uint8 把 81773 个负梯度截成 0，只剩半边边缘。
2. `-1` 与 `cv2.CV_64F` 的差别不是「精度」而是「符号」——后者才是信息量（32.7893 vs 16.0151）。
3. 梯度方向**垂直于边缘走向**：垂直边缘只让 `gx` 响应，`|gy|` 恰好 0。
4. `normalize` 后的图**只能看形状**：13907 级灰阶被压到 246 级，量化分析必须用原始浮点幅值。
5. **Scharr 与 Sobel 的绝对值不可比**（差 4.2501 倍），阈值必须重标定。
6. `cv2.Scharr(img, ddepth, dx=1, dy=0)` 与 `Sobel(ksize=cv2.FILTER_SCHARR)` 完全等价（差 0）。
7. Laplacian **ksize 不同结果根本不可比**（21 → 53 → 317，差 15 倍）。

9. Canny **输出只有 0/255**，不是灰度梯度图。
10. Canny 的「比例」比「绝对值」重要：1:3 是经验值，换图后绝对值全变但手感仍可用。
11. `L2gradient=True` 更严谨也更保守（17831 < 20630）；L1 会高估对角梯度（最多 √2 倍）。
12. 换 `apertureSize` **必须重调阈值**（3→7 边缘数从 20630 涨到 50329，2.4 倍）。
13. **滞回让边缘像素不全是「强梯度」**：5.51% 的边缘像素 mag 低于低阈值。
14. **阈值设 0 ≠ 没有边缘**：`Canny(0,0)` 仍有 54891 个（非极大值抑制后剩下的脊线）。
15. `Canny(255,255)` 仍有 10984 —— 梯度幅值本来就能超过 255。

**易错点**

2. 3×3 方块腐蚀后只剩**中心 1 个像素**；结构元的形状决定「边界动几格」。
3. **`ELLIPSE(3,3)` 就是 `CROSS(3,3)`**（5 个 1 元素），膨胀方块只得 21 px 而非 25。
4. `ELLIPSE(5,5)` 只有 17 个 1 元素（RECT5 是 25）——**ksize 相同、shape 不同，结果不可比**。
5. **矩形核下「迭代 n 次 3×3 ≡ 一次 (2n+1)×(2n+1)」**；换 ELLIPSE 就不成立。
6. 开运算 ≠ 闭运算（逐像素差 255），方向相反，**不能互换**。
7. **开去白噪点、闭填黑洞**：闭运算会把孤立噪点连成片（轮廓降了但前景变多）。
8. **洞必须严格小于核尺寸**才填得上：3×3 洞要 close5，5×5 洞要 close7。
9. `gradient = dilate - erode`、`tophat = src - open`、`blackhat = close - src`（差均为 0）。
10. 顶帽的大核版本可当**光照校正**用（`src - open ≈ 高频细节`）。
11. **`findContours` 在 OpenCV 4/5 只返回 2 个值**，老教程的 3 值写法直接 `ValueError`。
12. `RETR_EXTERNAL` 会**丢掉孔洞轮廓**（`cbw` 上 34 vs 61）。
13. `CHAIN_APPROX_SIMPLE` 省掉共线中间点（3703 → 1729 点，省 53%）。
14. **算周长必须 `arcLength(c, True)`**，否则少算闭合段（6.0）。
15. 轮廓面积用格林公式（3007.5），连通域面积数是像素（3097）—— **同一个目标两个数**，别混用。

**易错点**

1. `matchTemplate` 的响应图尺寸 = **场景 − 模板 + 1**，不是场景尺寸。
2. **极值口径不统一**：`SQDIFF` / `SQDIFF_NORMED` 看 **min**，其余四种看 **max**。
3. **未归一化的 `CCORR` 会定位到错误位置**（(244, 284) vs 真值 (200, 120)）——
   它只找「最亮的一团」，不管形状。
4. 归一化方法对亮度/对比度扰动**免疫**（≥0.988887）；但 `SQDIFF` 的分数从 **0**
   变成 **3674344**，**完全不可比** —— 阈值判断必须用 `*_NORMED`。
5. **命中像素数 ≠ 目标个数**：阈值 0.8 时 3 个目标只命中 3 个像素（峰值极尖），
   真实图像里一个目标会命中一整片。
6. 贪心抑制的**半径不能小于目标尺寸**，否则同一目标会被数两次。
7. **`matchTemplate` 返回 (x, y)，numpy 索引是 [y, x]** —— 画框与切片混用时必出错。
8. **模板匹配没有尺度不变性**：目标放大 1.25 倍后用原尺寸模板只有 **0.303955** 分；
   多尺度扫描能救，但**耗时线性增长**（22 档 = 22 倍）。
9. Harris 的 R **可以为负**，阈值只能写 `k * R.max()`，不能给绝对值。
10. 一个角点在响应图上**连成一片**：超阈值像素 27380 → NMS 后 **5934**。
11. **`np.where` 是行优先返回的**：直接取前 5 个拿到的是 y = 0 的弱角点（6e6 量级），
    真正最强的是 y = 185 的（3e8 量级），**差 50 倍**。取 top-K 必须显式 `np.argsort`。
12. `blockSize` 越大角点**越多**（27380 → 102027）；`ksize` 越大 R 量级**暴涨**
    （3.07e8 → 5.55e11，**必须重定阈值**）；`k` 越大 R.min 越负。
13. Shi-Tomasi 取 `min(λ1, λ2)`，**比 Harris 少一个要调的 k**。
14. **角点数口径必须写清楚**：Harris+NMS **5934** vs `goodFeaturesToTrack` **200**。
15. **参数「不起作用」常常是被另一个约束掩盖**：`qualityLevel` 被 `maxCorners` 掩盖
    （0.001~0.05 都是 200）、`fastThreshold` 被 `nfeatures` 掩盖（都是 500）。
16. ORB 描述子是 **256 bit 的 uint8** → 匹配必须用 **`NORM_HAMMING`**，不是欧氏距离。
17. 尺度是 **×1.2 的等比序列** + 每个关键点带**角度** = 尺度 + 旋转不变性。
18. `BFMatcher(crossCheck=True)` **不能再调 `knnMatch`** —— 直接断言失败
    （`K == 1 && update == 0 && mask.empty()`）。
19. Lowe 比率测试常用 **0.75**；RANSAC 单应 236/244 内点。
20. **旋转角符号坑**：y 轴向下 → 数学意义的「逆时针」对应**负角**
    （反推 −24.0895° vs 施加 +25°）。

**易错点**

1. IoU 交集宽高**必须夹到 0**；忘了会让「只接触」的两个框算出正面积。
2. 并集要**减掉一次交集**（`A + B` 把交集算了两次）。
3. **包含关系下 IoU 不是 1**：大框套小框退化成面积比（50×50 在 100×100 里 = 0.25）。
4. IoU 是**对称**的，写 `iou(p, q)` 和 `iou(q, p)` 结果必须一致。
5. 广播版 IoU 的坐标轴是**最后一维**：`a[..., 2]` 而不是 `a[:, 2]`。
6. 逐对版与矢量版必须**差 0.0**，否则说明边界口径不一致。
7. **IoU 是相对度量**：同样错 1px，20×20 掉到 **0.904762**，600×400 还有 **0.996672**
   —— 固定阈值天然对小目标苛刻。
8. YOLO 归一化的分母是**宽 / 高各自的**：`cx` 除宽、`cy` 除高。方图上看不出来，
   16:9 图上全错。
9. **YOLO 往返有损**：txt 存 6 位小数，转回像素差 **0.0005125**，验证必须用容差不能用 `==`。
10. `.txt` 的 `class_id` 是**数字**，映射回类别名要靠 `labels.json` 的 `classes` 数组。
11. **NMS 只与存活框比较**：thr=0.5 时标准版 `[0,2,3]`、错误版 `[0,3]`。
12. NMS 阈值扫描结果**不是单调的**（0.3 → 2 个、0.5 → 3 个、0.7 → 4 个）。
13. NMS 阈值要与**定位精度**匹配：抖动 ±3px 时 0.3~0.7 都能压回 10 个，0.9 就压不住（25 个）。
14. `cv2.rectangle` 的颜色是 **BGR**，`(0, 0, 255)` 才是红框。
15. `cv2.rectangle` 的厚度**向边线两侧扩展**：2px 线宽时实际改动范围比原框四周各多 1px。
16. **越界框必须先裁剪**，否则画不出来、切 ROI 切错、面积算大污染 IoU/NMS。
17. **一个 GT 只能被一个预测认领**，否则 recall 会虚高。
18. recall 的分母是 **GT 总数**，不是预测数。
19. **AP 要用单调化后的 PR 曲线**算，否则同一模型不同实现结果不一致。
20. **11 点采样会高估 AP**：稀疏曲线上 0.704545 vs all-point 0.625。

**易错点**

1. **`DIST_MASK_PRECISE` 的数值是 0**，不是 5（`DIST_MASK_3`=3、`DIST_MASK_5`=5）。
2. `maskSize=3` 是 3×3 chamfer 近似：**水平/垂直步长权重是 0.955 而不是 1.0** ——
   1px 细线的 `dist.max()` 从 1.0 掉到 **0.955002**（偏小 4.5%）。
3. 距离变换的输出是**逐像素图**；`dist == 0` 的地方就是背景本身。
4. `cv2.circle` 画的「圆盘」其实是**内接多边形**，45° 方向的弦被切掉 ——
   所以圆心的 `PRECISE` 距离是 **5√2 = 7.071068** 而不是 8。
5. 核心阈值必须写 **`f * dist.max()`**，写绝对值换张图就废。
6. **markers 约定只能记死**：`0` = unknown、`1` = 背景、`>= 2` = 目标。
   把 `sure_bg` 填成 0 会让整张图变成一个前景区。
7. `unknown` 是 **0/255 图**，`cv2.subtract(255, 1) = 254` ——
   判空必须写 `== 255`，写 `> 0` 会把核心也算进去。
8. `cv2.watershed` **就地修改** markers，复用时必须 `.copy()`。
9. **`ws.max()` 比目标数多 1**：`ws == 1` 是「背景区域」，不是一个目标。
10. **`ws == -1` 是边界线**，不属于任何区域；统计面积时必须剔除。
11. 面积统计用 `np.unique(ws, return_counts=True)` 最稳，
    `np.bincount` 遇到 `-1` 会直接抛 `ValueError`。
12. **粘连目标纯用连通域会少数**：合成图 **4 vs 8**，直接少一半。
13. 粘连块面积（5480）**小于**理论并集（5492.96）—— 模糊与噪声在啃边缘。
14. **阈值窗口不能背**：coins 要 0.2~0.3，合成图要 0.6~0.8。
15. 「核心数对了」≠「解对了」：还要检查**最小核心面积**有没有 1px 的伪核心。
16. **实例级与像素级指标会给出相反结论**：纯形态学的 Dice **0.998929** 比
    分水岭的 **0.982337** 更高，但它数不出 8 个目标。两个都要报。
17. 分水岭的 Dice 永远达不到 1.0 —— 它把 `ws == -1` 的边界线排除了。
18. `Dice` 与 `IoU` **单调等价**但量纲不同：IoU 0.1 → Dice **0.181818**（近一倍），
    IoU 0.9 → Dice 0.947368。汇报时必须写清用哪个。
19. 「错位半个身位」代价极大：4×4 方块错位 2px → Dice **0.25**。
20. **GrabCut 不可复现**：内部 GMM 的 k-means 初始化调用全局 RNG，
    不设种子四次结果全不同（16241/16196/16190/16235），**必须 `cv2.setRNGSeed`**。
21. rect 模式下 **`GC_FGD` 恒为 0** —— 只给了方框，算法不敢断言任何「确定前景」。
22. rect 是**硬边界**：前景 100% 落在 RECT 内（越出 0 像素）；
    mask 模式才能突破（bbox 从 (160,90,220,166) 撑到 (69,88,356,232)）。
23. iter 不是越大越好：1→16358、5→16254、10→16268，**没有单调收敛**。

**易错点**

1. **归一化的 mean / std 只能来自训练集** —— 拿测试集一起算就是信息泄漏。
2. `/255` 与「标准化」不是一回事：`/255` 后 mean 还有 **0.130011**、std **0.307255**。
3. `torch.from_numpy` 得到 **uint8**，`uint8 * 255` 会**溢出回绕**；整数除法直接丢小数。
4. `reshape` 会**搬数据**，`permute` 只换 stride —— 接 `cv2` 或 `unfold` 前常要 `.contiguous()`。
5. **残批**：2000/64 = 31 满批 + 1 个 16，**「步数」不等于那个小数**。
6. `drop_last` 丢 16 张（0.8%）换每批形状一致。有 BatchNorm 时残批尤其危险。
7. **`shuffle` 用 DataLoader 自己的随机源**，光设 `torch.manual_seed` 管不到它 ——
   必须传 `generator=`，否则两次训练看到的数据顺序不同。
8. 手写 `Dataset` 的 `__getitem__` 返回的标签可以是 **python int**，DataLoader 会自动 collate。
9. `F.unfold` + 矩阵乘 = 卷积（im2col + GEMM）；无 padding/stride 时 L = (H−KH+1)·(W−KW+1)。
10. 手撕与 `F.conv2d` 差 **9.537e-07** 是 float32 累加顺序不同，不是算法错。
11. **参数量全在 FC 层**（7840 / 9098 = 86%）；卷积层参数量与图像尺寸**无关**。
12. **模型最后一层不加 softmax** —— `CrossEntropyLoss` 内含 `log_softmax + NLLLoss`。
13. logits 行和**不是 1**；softmax 后才是 1。取类别用 `argmax(logits)` 即可。
14. 初始 loss ≈ **ln(10) = 2.302585**（实测 2.298519）—— 这是个很好的自检点。
15. 训练四步顺序不能错；**`zero_grad()` 必须调**（PyTorch 梯度默认累加）。
16. `loss.item()` 才脱离计算图；直接 `float(loss)` 会有 `requires_grad` 警告。
17. **训练满分 + 测试 0.96 = 过拟合**（2000 张训 9098 个参数）。
18. 轮数不是越多越好也不是越少越好：1 轮 0.800（欠拟合）→ 15 轮 0.960，
    **最优轮数只能靠验证集找**。
19. 混淆矩阵 **行是真值、列是预测**；行和 = 该类样本数（分母是真实类别数）。
20. 整体准确率会掩盖最差类：整体 0.960，但数字 8 只有 0.870370。
21. **复现训练结果要同时管三处**：`torch.manual_seed` + DataLoader `generator` + 调用顺序。
22. 小数据上经典特征依然强：HOG+LinearSVC **0.952** vs CNN **0.960**（只差 4 张）。

**易错点**

1. **算指标之前先做坏图体检与标注质检** —— 坏图混进统计会让指标无端变差。
2. Laplacian 方差 ≈ 清晰度，**越小越糊**；site_07 欠曝 0.047629（其他三张 ≤ 1.4e-03）。
3. **HSV 的 V 通道直接受亮度影响** —— 暗图会让阈值分割整体掉一批像素。
4. **「检出框数」≠「检出对不对」**：site_01 检出 28 个框而 GT 为 0。
5. **F1 = 0 时第一件事是排查「方法假设」，不是「参数」** —— 15 组参数全 0 说明方向错了。
6. 多色带并集**同时放大背景干扰**：黄+白让 TP 从 0 到 4，代价是 FP 从 64 到 101。
7. **「黄+白」的好看数字是巧合** —— 白带吞进大片亮区恰好框住一个头盔（见 §F1.10）。
8. **白/灰/黑的 S 低**，H 通道对它们只是噪声 —— `H 任意 + S<50 + V>200` 会吞掉 91.02% 的白背景。
9. 用**最大 IoU 做低成本探针**：长期 < 0.2 就别再调参了。
10. **GT 为 0 的图不该进召回分母**（site_01），否则会低估召回。
11. **CV 项目必须有一个「合成可控场景」作对照**，否则分不清「算法错」还是「数据难」。
12. 换方法的两条路：ch07 特征（HOG/LBP）+ 分类器 / ch09 候选框 + NMS。

7. **val 只有 400 张，3% 的波动是噪声**，别据此调参调过头。
8. 增强的合法性前提是**标签不变**；`np.repeat` 负责对齐顺序。
9. **增强必须确定性**（传 seed），否则实验没意义。
10. 增强会改变像素分布：std **79.33→75.87**、非零占比 **0.19→0.24**（`warpAffine` 插值灰边）。

12. `torch.manual_seed` + `DataLoader(generator=...)` 两处一起管才可复现。
13. **「深度模型更好」必须补「在多少数据上」**：100 张时 SVM 赢 0.068。
14. 反超点**不是 400 或 800，而是 1600**；要看的是两条曲线的**斜率**（SVM +0.014 vs CNN +0.040）。
15. **增强收益取决于「模型缺什么」**：HOG 本身平移不变 → SVM 只 +0.022；CNN 没有内置不变性 → +0.080。
16. 整体准确率掩盖最差类：数字 9 在 SVM 上只有 **0.789474**。

19. **低置信子集可直接当拒识门槛**：`conf < 0.9` 的 38 张里 42.11% 是错的（全体 4%）。

**易错点**

1. **像素级指标和实例级指标必须一起报** —— Dice 0.998681 但连通域只有 7 个（GT 9 个）。
2. 粘连目标在二值掩码里**必然合并**，纯连通域计数**一定会少**。
3. **分水岭核心阈值只能扫不能拍**：本章需 0.4~0.45，ch10 的 coins 要 0.2~0.3、合成细胞要 0.6~0.8。
4. 核心阈值太大反而变差（0.5 档：最小核心 2567、粘连最差 0.099423 恶化）。
5. **markers 约定**：`0` = 待定、`1` = 背景、`>= 2` = 目标；输出里 **`-1` 是 1 px 宽的边界线**。
6. `cv2.subtract` 处理 0/255 图；用 numpy 相减会在核心处得到 254 而不是 0。
7. `cv2.watershed` **会就地改 markers**，必须传 `.copy()`。
8. 区域面积之和 < 前景像素数（少的那些成了边界线）。
9. **等效直径 `2√(A/π)` 有系统性 -1 px 偏置**（孤立目标 -1.019971 px，相对 -1.43%）。
10. **圆度上限不是 1 而是约 0.87**（数字周长的阶梯效应）；偏差大就说明区域被切坏了。
11. **圆度/长宽比是免费质检指标** —— 不需要 GT 就能发现异常（GT#2 圆度掉到 0.519006）。
12. **「面积」有三种口径**：contourArea 比像素计数小 **2.7420%**，最小外接圆平均大 **13.41%**（最差 92.98%）。
13. **相对误差 ∝ 1/直径**（相关系数 -0.970140）—— 小目标测不准是几何必然。
14. **`cv2.watershed` 的最终边界由图像梯度脊线决定，不由二值掩码决定** —— 掩码只提供标记点。
15. 因此分水岭路线**几乎免疫阈值**（-0.000667 px/10），代价是固定偏置；
    纯阈值路线**准但不稳**（+0.310897 px/10）。
16. **标定件不能用来自评精度**（GT#0 被校正成误差精确 0），必须用别的目标评估。
17. 真实图（coins）**没有精确 GT**，报告口径只能是「计数 + 尺寸分布 + 形状质检」。
18. **`cv2.addWeighted(vis, 0.7, ov, 0.3, 0)` 会改动整幅图**（307200 px），不只是叠加区。
