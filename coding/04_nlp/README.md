## 四、写作纪律（与全仓一致）

- 三件套：`chNN_<短名>.ipynb`（讲解）/ `_practice.ipynb`（挖空）/ `_solution.ipynb`（答案），
  由 `scripts/authoring/nlpNN_*.py` + `scripts/nb_builder.py` 生成，**不手写 practice**。
- 每章 `assert` 真值必须**实跑**，禁止手算填数；探针脚本写在 `/tmp/`，不入库。
- **断网可跑**：不下载预训练权重、不调用在线分词 API。
- 挖空块内**不得出现控制流**（`for` / `if` / `def`），续行不得以 `for` / `if` 开头
  （`nb_builder` 会抛 `BuildError`）。
- notebook cwd = `coding/04_nlp`，所以数据路径用 `Path("data")`。
- 中文绘图：设 `plt.rcParams["font.sans-serif"] = ["PingFang SC", ...]` + `axes.unicode_minus=False`；
  **不要**调 `matplotlib.use("Agg")`、也**不要**调 `plt.show()` —— 让 ipykernel 的 inline 后端接管
  （设了 Agg 图就不显示，调了 show() 在非交互后端会告警）。
- 涉及 `nn.RNN` / `nn.Embedding` 等随机初始化的实验，一律用
  `with torch.random.fork_rng(): torch.manual_seed(k)` 隔离，保证结果与执行顺序无关。
- 章节要点、易错点、难点索引随章节交付同步追加到本文件 §六。

**易错点**

1. **忘了 `h.retain_grad()`** —— 循环里的 `h` 不是叶子张量，`h.grad` 是 `None`，**不报错**只是拿到空值。
2. **拿未训练的 RNN 做顺序性实验** —— 本节实测 cos **0.98**，结论会完全反过来。
3. 以为把谱半径调到 1 就不会梯度消失 —— `tanh' ≤ 1`，**tanh 自己也在衰减**（实测每步 ×0.746）。
4. `h0` 传 2D —— `RuntimeError`，要 `(num_layers, B, D_H)`。
5. 单样本输入时以为 `batch_first` 还生效 —— 2D 输入输出也是 2D。
6. 反向循环里 `dh` 忘了回传 —— 梯度只反映最后一步，数值偏小。
7. 反向循环里写 `if t > 0` —— 可用「状态表前移补零」消掉，代码更短也不易错。
8. 重复创建 `nn.RNN` 时不隔离 RNG —— 结果随执行顺序漂移，`assert` 时好时坏。
9. 用 `acc == 1.0` 这种脆断言 —— 改用 `> 0.99`。
10. 把「准确率高于 0.5」当成有信号 —— 小样本上纯噪声也能到 0.52。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| `retain_grad` | 静默返回 `None`，看不出错 | §3.7 |
| 梯度消失的归因 | 都怪 `W_hh` 谱半径会漏掉 tanh 这一半原因 | §3.8 |
| 谱半径与每步因子的区别 | 一个是单步雅可比，一个是 50 步平均 | §3.8 |
| 加性捷径的双面性 | 不衰减了，但可能开始爆炸 | §3.9 |
| 未训练网络上的实验 | 结论可能完全反向，且看起来很有说服力 | §3.11 |
| 无信息特征的假信号 | 0.52 看着像信号，n 推到 2 万就现形 | §3.13 |

**核心结论（一章一句话）**：Attention 是对 RNN 三个硬伤的直接回应 ——
**梯度要连乘 50 次**（实测每步 ×0.746）、**串行不可并行**（长度 ×16 耗时 ×14.7）、
**长距离顺序信息难保持**；而「加性捷径让每步因子从 0.746 升到 1.121」这一条，
正是「任意两位置直接连边」的思想原型。

**易错点**

1. **`nn.Transformer` 默认 `dropout=0.1`** —— 不显式写 `0.0`，训练结果不可复现（最容易踩）。
2. **以为 `fork_rng` 保证可复现** —— 它只还原到「进入时的状态」，那个状态默认是随机的。
3. **lr 写在 `opt.step()` 之后** —— 第一步会用初始满 lr，warmup 白做一格。
4. **label smoothing 后还期望 loss 归零** —— 平滑给 loss 设了下界。
5. **只报 token 准确率** —— 序列任务会严重高估（本章差 **0.2237**）。
6. **长度惩罚写成 `score * len**α`** —— 分数是负的，乘会让长句更差，必须**除以**。
7. **beam search 里漏掉「已结束序列」** —— 已吐 `<eos>` 的前缀继续扩展会污染候选池。
8. **把 oracle 与 TF 逐位置当两个实验** —— 实测逐位相等，本质是一回事。
9. **挖空块里写 `if` / `for`、或让续行以 `if` / `for` 开头** —— `nb_builder` 直接 `BuildError`。
10. **用 `trim` 后的变长序列去 `torch.as_tensor`** —— 形状不齐会 `ValueError`；
    逐位置对比要用**未裁剪**的定宽输出（本章真踩过）。

**易错点**

1. **`[SEP]` 的 segment id 写错** —— 句对里**第一个** `[SEP]` 属于前一句（seg=0）。
2. **截断时不补 `[SEP]`** —— 句尾未闭合，`[CLS]` 表征会漂。
3. **WordPiece 的 `##` 加错位置** —— 它是给**续接片段**的，词首不加。
4. **以为 WordPiece 会部分匹配** —— 一个片段失败就整词 `[UNK]`。
5. **MLM 全用 `[MASK]`** —— 10% 随机替换 + 10% 原样保留不是装饰。
6. **交叉熵忘了 `ignore_index=-100`** —— padding 会被算进 MLM 损失。
7. **LoRA 的 `B` 不置零** —— 训练第一步就毁掉预训练权重。
8. **`alpha` 与 `r` 混用** —— 缩放系数是 `alpha / r`，只改 `r` 会同时改有效学习率。
9. **以为预训练一定涨点** —— 实测随机初始化 **3 胜 1 平 0 负**，
   且 5/10 条时大语料预训练反而**更差**。
10. **`ModuleList` 的数字下标不能 `getattr`** —— 替换子模块要写
    `parent[int(q)] if q.isdigit() else getattr(parent, q)`（本节 `to_lora` 真踩过）。
11. **在 MPS 上用默认 dropout** —— `attention_probs_dropout_prob=0.1` 会让
    `scaled_dot_product_attention` 直接 `NotImplementedError`；
    设成 `0.0` 即可（顺带也满足「训练可复现」）。
12. **HF 的层名照抄成 `("q", "v")`** —— HF 用 `query` / `value`，
    传错**一层都替换不到，而且不报错**，你会以为自己做了 LoRA，其实在全量微调。
13. **以为 `to_lora` 会冻结整个模型** —— 它只冻结被替换的那一层，
    其余 key / output / FFN 仍是 `requires_grad=True`，必须手动再冻结一遍。
14. **照抄老教程写 `warmup_ratio`** —— transformers 5.17 的 `TrainingArguments`
    已无此参数（只剩 `warmup_steps`），直接 `TypeError`。
15. **不看 `lr_scheduler_type` 就用 `Trainer`** —— 默认 `linear` 会把 lr 线性衰减到 0，
    400 步的训练里准确率比 `constant` **低 0.0596**。

**核心结论（一章两句话）**：

① 本章得到一条**高价值负结果链** —— 在这个规模（11.4 万参数 + 6 种句式 + 570 条下游数据）下，
**MLM 预训练打不过随机初始化**：§7.8 的数据量矩阵上是 **3 胜 1 平 0 负**，
§7.14 换到四种微调策略上是 **4 胜 0 负**（含全量微调 **0.617021 vs 0.389362**），
扩大到 35 倍语料也无法翻转。由此把「预训练有用」立成**有条件的结论**
（容量 / 语料多样性 / 下游任务性质）。

② LoRA 部分独立立住，且**手写版可以直接挂到真实模型上**：

① **jieba 完全可复刻** —— 它 = 前缀词典 + DAG + 对数概率 DP + **英数符合并** + HMM。

这条 `0 → 570` 的反差本身就是最好的「别跳过收尾逻辑」教材。

② **能复刻 ≠ 该用它** —— 在这批电力工单上，**手写词表反而更贴数据**
（`电流互感器`、`隔离开关`、`请核实后反馈` 手写切对、jieba 切错），

分词的价值不在「切得多准」，而在「信号词是否唯一指向标签」——
判断「该不该在分词上花时间」比把分词调准更重要。

> ⚠️ 但**不要**由此得出「jieba 没用」：§8.2 里手写版之所以赢，是因为它的词表
> 是**照着这个数据集造的**。换到任何一份没有词表的新语料，手写最大匹配会立刻退化，
> 而 jieba（+ 一份用户词典）是唯一能马上跑起来的选择 —— §8.9 已经验证了这一点。

**易错点**

1. **换语料不固定评测集** —— 先按 A 切分再按 B 切分，两次查询集不同，指标差多少说不清。
   本章的清洗对照是**同一批行只换清洗函数**，这才是受控实验。
2. **以为 `N/A` 在 ch01 处理过就没了** —— 它不在 STOP 里、也不是空串，
   会变成 `N` / `A` 两个 token 进入索引，**还拿到全库最高 idf**（idf 只认统计不认语义）。
3. **忘了 `jieba.initialize()`**（同 ch08）—— `jieba.dt.total = 0`，取对数直接 `ValueError`。
4. **用 `log(N/n)` 当 idf** —— 常见词会得到**负 idf**，把排序彻底搞乱（本章用 `log(1 + ·)` 恒 ≥ 0）。
5. **以为 `R@5 = 0.10` 说明检索很差** —— 正样本中位 13 条，上限只有 **0.3798**，
   实际达到了 **26.7%**；同一次检索 `Hit@5 = 0.7759` 才是"有没有找到"的答案。
6. **只看 `R@k` 不看 `Hit@k`** —— 多正样本场景下前者会被"正样本条数"稀释。
7. **以为稠密向量一定更好** —— 词表只有 **70** 个词时 `SVD(64)` 解释方差 **1.000000**（无损），
   指标与 TF-IDF 逐位相同 —— **小词表上稀疏的精确匹配更稳**。
8. **以为 `RRF` 的 `k` 需要调** —— 实测 10/30/60/100 **完全相同**；融合的收益取决于**两路是否互补**。
9. **重排时不做分数归一化** —— BM25 的 0~20 分会压死向量的 0~1 分，加权退化成"只留 BM25"。
10. **以为 `Hit@5` 与 `MRR` 的最优点总是一致** —— 前者要广度、后者要精度，
    `b=0.5` 与 `b=1.0` 给出的最优不同。
11. **取最大/最小不管并列** —— `max(dict, key=...)` 返回"先遇到的"，
    而 dict 由 `set` 累加而来，**`set` 迭代顺序受字符串哈希随机化（`PYTHONHASHSEED`）影响**：
    `idf` 最高的 `N` 与 `A` 完全相等，换个进程跑可能换个词被选中。
    **凡"取极值"处都要定 secondary key**，否则"同样输入两次跑出不同 top-1"。
12. **打印"逐词贡献"时词表与数值来源顺序不一致** ——
    一边 `sorted(set(...))` 一边 `set(...)`，打印出来就是**错位的对照表**，
    会得出"模板词 idf 最高"这种完全相反的结论（本章真踩过，靠 `sum(contrib)` 对账才发现）。
13. **索引脏数据与查询脏数据混为一谈** —— 前者主要污染 `avgdl`（全库分数整体偏移），
    对 top-k 影响有限；后者（一条 `N/A` 查询）会让**一次检索彻底失效** → 这才是拒答要解决的。
14. **拒答阈值拍脑袋** —— 要画出"真命中最低分（4.507）"与"干扰最高分（3.174）"之间的**缝隙**，
    并在缝隙里留余量（测试集只有 6 条干扰查询，边界不稳）。
15. **prompt 里写"请综合你的知识作答"** —— 那会让模型绕过资料自由发挥，与 RAG 初衷相反。

**难点索引**

| 难点 | 为什么是坑 | 位置 |
|---|---|---|
| 清洗深度 vs 换算法 | 直觉是"效果差就换模型"，实测清洗 **+0.045** vs 换算法 **+0.02** | §任务 1 §任务 6 |
| `avgdl` 的全局性 | 脏数据不改排序，但改**所有文档**的分数尺度 | §任务 2 |
| idf 只认统计 | `N`/`A` 拿到最高 idf，而它们来自占位符 | §任务 3 |
| 多正样本的指标语义 | `R@5` 低 ≠ 检索差，必须报上限 | §任务 7 |
| SVD 在 70 词表上无损 | "向量检索更强"这条经验在**小词表**上不成立 | §任务 8 |
| 归因驱动改进 | 看总量指标给不出方向；看误差**结构**才有方向 | §任务 11 §任务 12 |
| 拒答只能处理词法无关 | 「变压器的工作原理是什么」这类**意图不匹配**拦不住 | §任务 13 |
| 评测纪律 | 换语料必须固定评测集，否则数字不可比 | §任务 1 §任务 2 |

**核心结论（一章两句话）**：

① **检索效果不好，先别换算法** —— 改进顺序是
**修数据（+0.045）→ 定口径（多正样本要报上限）→ 看误差归因（40% 是"设备跑偏"）
→ 定向改进（元数据过滤 + 词族加权，**+0.323**）→ 最后才轮到调算法（±0.02）**。
这套顺序在"有结构化元数据 + 有专业词表"的场景（电力 / 金融 / 法律）里普遍成立。

② **拒答的必要性来自实测** —— 完全无关查询的 BM25 得分**恰好是 0.000**
（词一个都不在语料里），这让"零分即拒答"成为免费能力；
但「含语料词但意图不同」最高能到 **3.174**，说明**分数阈值只能处理词法层面的无关**，
意图层面的不匹配要靠意图路由 —— 阈值 **4.0** 在这份数据上是干净的分割点。

**易错点**

1. **先统计后过滤** —— 30 条空文本会让平均 token、词表、loss 全部失真。
2. **用随机切分代替分层切分** —— 5 类各 120 条，随机切分会让某些类在测试集只剩十几条。
3. **拿全量建词表** —— 最隐蔽的泄漏；必须只用 `TR`，并**报出测试集新词率**。
4. **基线用 `CountVectorizer` 默认 tokenizer** —— 分词口径一换，比出来的就是「分词差异」。
   实测这一项会把结论**反转**（0.8588 vs 1.0000）。
5. **`lr` 写在 `opt.step()` 之后** —— 第一步会用满 lr，warmup 失效。
6. **混淆矩阵转置** —— `cm[真值, 预测]` 与 `cm[预测, 真值]` 讲的是两个不同的故事。
7. **只看准确率** —— 异类 FP=0 但 FN=3，只有逐类 P/R/F1 才看得出来。
8. **把 max 池化的提升当「修好了」** —— 0.994118 的收益同样落在噪声带内（§14 会证明）。
9. **用单次实验下结论** —— 换 seed / 步数能让准确率在 0.976471 ~ 1.000000 间摆动，
   **摆动幅度大于两个模型的差距**。
10. **`torch.random.fork_rng()` 不固定种子** —— 它只**还原**进入前的 RNG 状态；
    必须 `fork_rng` + `manual_seed(seed)` 双管齐下才能跨进程复现。

| 难点 | 为什么是坑 | 位置 |
|---|---|---|

**核心结论（一章一句话）**：本题的结论**不是**「Transformer 不如词袋」，而是 ——
**在这个任务上两者统计上不可区分，那就选便宜的**（555 参数 / 0.02 秒 vs
44741 参数 / 3 秒）；并且这个「不可区分」是**用一次正经的错误归因 + 一次灵敏度分析
换来的**，而不是靠一句「大模型更强／更弱」。三步可复用的方法论：

1. **先建最笨的基线**，并保证与正文**同一套预处理口径**；
2. **对差异做归因**（切片到子群 + 统计分布），而不是对差异做解释；
3. **在报告任何差距之前先量化噪声带**（换 seed / 换步数）。
