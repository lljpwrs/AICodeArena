### 2.1 合成模型（乘法，`基线 × 各因子`）

```
负荷 = 基线
     × 日周期   （居民型：20 点单峰；工业型：13 点超高斯单峰）
     × 年季节   （冬峰 1 月中 + 夏峰 7 月中）
     × 周周期   （工作日 / 周末系数）
     × 节假日   （6 段共 28 天 = 672 h）
     × 温度效应 （制热 / 制冷两段线性）
     × 年趋势   （缓慢爬升）
     × (1 + 噪声)
```

| 台区 | 类型 | 基线 | 周末系数 | 节假日系数 | 制热系数 | 制冷系数 |
|---|---|---|---|---|---|---|
| `STATION_A_01` | 居民型 | 520 | 1.06（**周末更高**） | 0.82 | 0.011 | 0.017 |
| `STATION_B_02` | 工业型 | 880 | 0.62（**周末砍半**） | 0.45 | 0.005 | **0.000（不制冷）** |

> 两个台区的**形态刻意做成反向**：A 是双休更忙的居民曲线，B 是周末停摆的工业曲线。
> 这样 §1.6 的「A-B 日周期形状相关 ≈ 0」才有教学意义 —— 不是数据没造好，是**本来就不该相关**。

#### 易错点（18 条）

1. **`drop_duplicates` 一定要在 `set_index("时间戳")` 之前**。之后再做，重复时刻已经污染了索引。
2. **`asfreq` ≠ `resample`**。前者对齐补 NaN，后者真聚合。想"数出缺失了几小时"只能用前者。
3. **`pd.to_datetime` 遇到中文日期会直接失败**，`format="mixed"` 也救不了 —— 先做字符串归一化。
4. **`to_numeric(errors="coerce")` 不认千分位逗号**，`"1,234.5"` 会被静默变成 NaN。先去逗号。
5. **周期整数（小时 / 星期 / 月份）必须 sin/cos 编码**，否则 23 点与 0 点成了一根线上的两端。
6. **`shift` / `rolling` / `diff` 不分组 = 跨实体污染**。判断方法：数分组前后的 NaN 个数。
7. **`rolling(n)` 默认 `min_periods=n`**，一个 NaN 毁掉整个窗口。70 个缺失 → 1009 行不可用。
8. **构造滑窗特征前先 `shift(1)`**，否则窗口含当前时刻，而当前时刻与目标高度相关。
9. **异常值检测的阈值要分组**。双峰分布（工业负荷）用全局中位数会误杀整段日间峰（实测 **382** 个）。
10. **先清洗再算自相关**。不清洗时 1 步自相关 0.277，清洗后 0.869 —— 差了一个量级。
11. **`lag24` 可能比 `lag1` 更有用**，因为周期对齐比"离得近"更重要。
12. **时序只能按时间切分**。随机切分让 MAE 虚降 1.12，且完全不报错。
13. **特征窗口绝不能覆盖 `y` 所在区间**。`shift(-1).rolling(24)` 这类写法必须一眼识破。
14. **标准化参数只能来自训练段**。哪怕本数据上测不出差别（+0.000007），也要照做。
15. **`center=True` 的移动平均没有相位滞后**；不加的话趋势项会晚半天。
16. **分解完要看残差 ACF**。平坦不衰减 = 有慢变结构；在周期整数倍处出峰 = 周期没拆净。
17. **乘性数据要取对数**。判据：高/低负荷段的残差 std 比 > 1.1。
18. **温度对负荷是 V 形**。线性相关系数 −0.19，换成 `|T−22|` 就是 +0.41。

#### 易错点（20 条摘录）

1. **τ 统计量不服从 t 分布**。哪怕 n=8759，也必须查 DF 临界值表（`"c"` 5% ≈ −2.86、`"ct"` ≈ −3.41）。
2. **ADF 的 p 值对滞后阶极其敏感**。同一序列 7 档里能有 1 档给出完全相反的结论 ——
   报 p 值必须同时报 `maxlag` 或 `autolag` 的选择。
3. **`adfuller` 必须显式传 `result_object=False`**，否则返回的是对象不是元组。
4. **`adfuller` 返回元素个数取决于 `autolag`**：`autolag=None` 只返回 **5** 个（无 IC），
   `autolag="AIC"` 返回 **6** 个。直接 `r[5]` 会在前者上 `IndexError`。
5. **差分不是越多越"平稳"**。判据两条：**方差比 > 1** 且 **ACF1 转负** ⇒ 差过头了。
6. **ACF 的分母口径要统一**。`adjusted=False` 用 n 项，`True` 用 n−k 项；两者在小 n 上可见差异。
7. **Bartlett 带是 `±1.96/√n`**，不是 `±1.96/√(n−k)`；且它只在白噪声假设下成立。
8. **PACF 有两种定义**（Levinson 递推 vs AR(k) 回归末系数），实测差 **1.18e-02** ——
   "手写 PACF 与库对账"时必须先声明用哪一种。
9. **AR 拖尾、MA 截尾**；ACF 与 PACF 要**放在一起**读，单独看一个必错。
10. **AIC 与 BIC 不是一回事**。本例两者同选 (1,2)，但样本量再小一点 BIC 会往低阶跑。
11. **残差 Ljung-Box 不过，先怀疑阶数不够，再怀疑模型族选错**。
12. **季节差分用 `diff(24)` ≠ 差分两次 `diff()`**。前者扣掉日周期，后者扣掉的是趋势+周期。
13. **`.loc[2, "AIC"]` 在 `(p,q)` 网格表里会拿错行** —— 行序是 `(0,0),(0,1),(0,2),(1,0)…`，
    位置下标 2 对应 `(0,2)` 不是 `(1,2)`。要按名字取。
14. **手写 ADF 的设计矩阵列序是唯一难点**：`y_{t-1}` 必须截到 `len(d)`，否则维度对不上。
15. **`p=0` 时不要 `np.column_stack([])`**（`ValueError: need at least one array to concatenate`）。
16. **`ARIMA` 的 `order` 里 d>0 时不能再用 `pandas.Series` 的索引对齐**，它按位置算。
17. **SARIMA 的季节项 `(P,D,Q,s)` 里的 s 必须与实际周期一致**，写 7 而数据是小时级的会静默变差。
18. **趋势项回归式（`"ct"`）比常数项（`"c"`）更不容易拒绝** —— 带趋势的序列用 `"c"` 会误判。
19. **`np.linalg.inv(X.T @ X)` 不如 `np.linalg.lstsq` + `se` 公式稳健**（病态设计矩阵会炸）。
20. **对账要报「最大绝对差」而不是「大概一样」**。本章两处对账分别是 `4.974e-14` 与 `3.331e-16`。

#### 易错点（14 条）

1. **标签是窗口后一格**，不是窗口末格。写成末格 = 把答案塞进特征。
2. **`sliding_window_view` 要 `[:-1]`**，否则 `X` / `y` 长度差 1（8760 → 8736）。
3. **`batch_first` 默认 `False`**，输入被当成 `(T, B, D)`。忘了它不报错、只全错。
4. **公式里的 `b_h` 是两个偏置之和**（`bias_ih_l0 + bias_hh_l0`）。
5. **torch 权重是 `(out, in)`**，numpy 里手写要 `.T`。
6. **`h_n` 形状是 `(层数×方向数, B, H)`**，单层单向时是 `(1, 3, 5)`。
7. **BPTT 里 `dh_t` 要加上本步输出那一项**，漏了梯度直接变全 0（相对误差 1.0000）。
8. **`dh_next = da @ W_h` 后面不要再乘 `tanh'`** —— 多乘会让梯度偏 8.9%~13.3%，还不报错。
9. **`ref.zero_grad()` 要在 `backward()` 之前**，否则 `.grad` 会跨轮累加。
10. **梯度实验的 loss 必须只挂最后一步**，否则量出来的是"假的不衰减"（比值在 0.3~1.5 乱跳）。
11. **标准化参数只能来自训练段**（`SERIES[:cut_pt]`）。
12. **报 MAE 必须同时报朴素持续基线**（0.414592），否则 0.2597 这个数没有意义。
13. **`tanh' ≤ 1`**：谱半径只是衰减率的上界，实测每步因子 = ρ × tanh'。
14. **输入幅度越大衰减越快**（饱和），所以"把 `W_h` 调大"救不了 RNN。

#### 易错点（14 条）

1. **PyTorch 的 LSTM gate 顺序是 `i, f, g, o`**，写成 `f, i, o, g` 后 `h` 差 4.741e-01，且不报错。
2. **只对调 `i` 与 `f` 一样错**（差 1.227e-01）—— 错的不是"顺序"这个概念，是每一个具体位置。
3. **GRU 的段序是 `r, z, n`**（reset / update / new），不是 `z, r, n`。
4. **GRU 的 `n` 门不加直连的 `b_hh`**：它在括号里，要被 `r_t` 乘（写错差 0.1552）。
5. **LSTM 四个门都加 `b_ih + b_hh`**；别把 GRU 的习惯带过来。
6. **`out` 的最后一维 = `H × 方向数`**；`h_n` / `c_n` 的最后一维**永远是 `H`**。
7. **`h_n` / `c_n` 第 0 维 = `层数 × 方向数`**，不是批大小（单层单向是 `(1, B, H)`）。
8. **GRU 没有 `c_n`**，写 `out, (h, c) = gru(x)` 会解包失败。
9. **双向不能用于在线预测**：后向分支要看未来，实时场景里那些值还不存在。
10. **门控 ≠ 自动解决梯度消失**：LSTM 默认 `f = 0.5`，T=160 首末比 3.952e-34，比 RNN（9.615e-13）还差。
11. **遗忘门偏置的切片是 `bias_ih_l0[H:2*H]`** —— 同时依赖"四段"与"`i,f,g,o` 顺序"两个知识。
12. **门控的收益不总是大**：24 步任务上 LSTM 只比 RNN 好 17%，双向（0.225713）甚至略差。
13. **对账必须用 double**：`float32` 只有 1e-7 精度，分不清"对"和"差一点"。
14. **随机性一律包 `fork_rng` + `manual_seed`**，否则与 ch03 的 MAE 表对不上。

#### 易错点（16 条）

1. **`horizon=1` 的 MAE 不能冒充 24 步**。本章 14.544809 vs 16.630607，差 14.3%。
2. **切分处必须留 `gap`**。窗口长 96，就一定有 95 个样本跨在切分点上（实测 95）。
3. **递归的第一步必须与单步 MAE 逐位相等**（`< 1e-9`）。
4. **递归滚动时一定要丢掉窗口最老的点**（`win[:, 1:]`）。
5. **「直接多输出避免了误差累积」不等于它更好**。本章它比递归差 0.066 kW，第 1 步就差 0.267 kW。
6. **`tf=1.0` 训练 loss 最低，但推理时最差**（21.12 vs 20.58 / 18.24）—— **严格单调**。
7. **训练 loss 不是模型选择依据**。
8. **`tf=0.0` 要配梯度裁剪**，否则早期自噪声会让它炸成 NaN。
9. **RNN / Seq2Seq 必须做梯度裁剪**（`clip_grad_norm_(params, 1.0)`）。
10. **不能只报一个平均 MAE**，逐步曲线可能是平的也可能是爬升的。
11. **朴素基线必须进报告**。seasonal naive 只要一行代码，却是本章所有模型的及格线。
12. **尺度还原别忘**：`Z = (S - MU) / SD` 训练，`* SD + MU` 才是 kW。
13. **`MU` / `SD` 只能用训练段拟合**。
14. **权重初始化也是随机数**：只在训练循环里 `manual_seed` 不够，实例化也要包在 `fork_rng` 里（本章 `build()`）。
15. **推理时至少 `.detach()` 或 `torch.no_grad()`**。
16. **Seq2Seq 输给 MLP 是数据决定的**（单变量强周期），不是实现 bug。

#### 易错点（18 条）

2. **光伏 / 风速 / 轻载场景禁用 MAPE**，用 `WAPE`（分母换总量）或 `sMAPE`（上界 200%）。
3. **`RMSE` 不是 `MAE` 开方**，是 `MSE` 开方。`MAE` 开方得到的是一个没有名字的数。
4. **`RMSE ≥ MAE` 恒成立**，看到 `RMSE < MAE` 一定是代码写错了。
5. **`RMSE/MAE` 要一起报**：1.286676 说明误差近似高斯；> 1.4 先查离群点。
6. **验证段必须按时间切**，随机切会让早停看到未来。
7. **`clip_grad_norm_` 必须在 `backward()` 之后、`opt.step()` 之前**；**返回值**是裁剪前范数。
8. **`sched.step()` 在 `opt.step()` 之后**调（PyTorch 2.x 的纪律）。
9. **`stopped_epoch = best_epoch + patience`** 是恒等式（实测 14 + 5 = 19）。
10. **早停只保存权重是错的**，还要 `break`，否则永远不知道「最好」在第几轮。
11. **递归预测的输入必须重新标准化**（`(p - MUY) / SD`），忘了就是量纲灾难。
12. **递归误差方差放大指数远小于 0.5**（实测 h^0.0861）。
13. **直接多输出与递归各有胜负**：整体 17.035627 vs 17.266384（直接赢），h=1 是 15.1762 vs **14.9523**（递归赢）。
14. **`autocorr` 与手写 ACF 分母不同**，lag 大时必须说明口径。
15. **`h=24` 残差自相关还很高（+0.5439）**，说明远期预测退化成朴素解 —— 结构问题，不是调参问题。
16. **统计显著不代表重要**：−0.22% 的偏差也能有 t = −2.33。
17. **残差按小时分组的「均值形状」和「标准差形状」是两件事**（偏差 vs 异方差）。
18. **涉及随机性的指标不能卡死值**，用区间断言；只有朴素基线 / 指标函数才卡死值。

| §7.1.1 | MAPE 的零点陷阱，一个 0.05 的点能毁掉整份报告 | 单点 `0.05 vs 5.0` → MAPE **9900%** / sMAPE **196.04%**；MAE 143.890302 / RMSE 243.244359 |

#### 易错点（16 条）

1. **OMP 运行时要先限线程再 import**：lightgbm 的 `libomp` 与 torch 的 `libiomp` 在 macOS/arm64 上
   各自开满线程会撞出 `OMP: Error #179`，**内核直接段错误**（不是 Python 异常，`try/except` 抓不到）。
   必须在 `import` **之前** `os.environ["OMP_NUM_THREADS"] = "1"`。这是本章踩得最深的坑。
2. **朴素基线不是「陪跑」**：`seasonal naive t-168` 一行代码拿到 31.560227，`last value` 要 60.524392 ——
   同样叫「基线」差一倍。选错基线会严重高估自己的进步。
3. **`last value` 的 24 步 MAE 最差（60.52），但 h=24 反而最小（21.61）**：h=24 时它恰好对上了同一个小时。
   只看一个总数会得出完全错误的结论，必须看逐步曲线。
4. **`moving average` 打不过 `t-24`**（45.53 vs 33.00）：24 小时均值把日周期抹平了。**平滑 ≠ 准确。**
5. **`t-168` 比 `t-24` 好**（31.560227 vs 32.998794，差 4.4%）：说明**周周期比日周期值钱**，
   这直接决定了特征工程要给 `lag168` / `ma168`。
6. **日历周期整数必须 sin·cos，树模型也不例外**：整数 `hour` 让 23 点与 0 点「离得最远」，
   树得堆很多层才能切开；sin·cos 编码后一次 `hour_cos >= 0.966` 的分裂就能圈出「深夜」。
7. **温度要按 V 形处理**：负荷对温度不是线性关系，所以特征给
   `temp`（线性分量）+ `temp_dev = |T − 22|`（V 形分量）两列。
   （ch01 实测：温度的线性相关系数 −0.19，换成 `|T−22|` 就是 +0.41。）
8. **LightGBM 的 `eval_set=` 已弃用**，新版要用 `eval_X=` / `eval_y=` + `lgb.early_stopping(n)`。
9. **验证段必须是训练段内部的最后 15%**（`vc = int(cut * 0.85)`），绝不能碰测试段 ——
   否则早停就用测试集调参了。
10. **每个步长一个模型**（24 个）比「单模型 + h 特征」更准，代价是 24 倍训练时间；
    递归最便宜但误差累积（ch07 §7.3.1）。
11. **因果卷积只补左边**：`F.pad(x, (pad, 0))`，`pad = (k-1)*d`。补右边就是把未来混进现在。
12. **搭 TCN 第一步是算感受野**：`RF = 1 + (k-1)·Σ2d = 61`，必须用扰动法实测对账；
    `RF < 窗口` 意味着最前面 11 格对预测毫无影响。
13. **ProbSparse 在 L=72 上并不更快**：只省 38.9% 的打分次数，却多付随机采样 + top-k 的开销
    （实测 19.6 s vs 全注意力 12.6 s）。稀疏注意力的收益要等 L ≥ 500。
14. **`u` 只按对数增长**：L 从 72 涨到 1440（20 倍），u 只从 22 涨到 37（1.7 倍）——
   这才是 ProbSparse 能省 95% 的原因。
15. **蒸馏砍的是分辨率不是冗余**：72 → 36 → 18 后每格代表 2 小时，日峰谷的相位会出「阶梯感」；
    Informer 的蒸馏是为 L = 1440 设计的，别照搬到 L = 72。
16. **深度模型的 MAE 必须用区间断言**：种子固定也会因线程数 / 算子实现漂移；
    能卡死值的只有朴素基线与感受野公式这类确定性量。

#### 本章小结（写在 notebook 里的结论：什么时候该上深度模型）

```
六条判据（该上深度模型 / 该留在 LightGBM·统计模型）
  样本量     单序列 > 10 万点、或多序列合并训练   /  单序列几千~几万点（本章 8760）
  外生变量   变量多、交互复杂、要端到端学表征     /  变量可枚举、能手工造强特征
  预测形态   概率预测 / 多变量联合 / L ≥ 500      /  单点预测、24 步以内
  周期结构   周期不规整（多周期叠加、周期漂移）   /  周期规整，lag24/lag168 就够
  算力预算   有 GPU、能训几十轮                   /  CPU、两分钟要出结果
  可解释性   不需要                               /  需要特征重要性写报告

三条实测证据
  ① TCN 打不过 LightGBM：RF=61 覆盖不到周周期 168，而 LightGBM 有 lag168/ma168
  ② ProbSparse 在 L=72 上省不下时间（省 38.9% 打分次数，反而慢 7.0 s）
  ③ Transformer 训满全部 6855 样本 × 20 轮，仍差 LightGBM 4.31 kW（20.03 vs 15.72）

一句话（可以背）：
  先把朴素基线和 LightGBM 打满，再决定要不要上深度模型。
  深度模型不是更高级，只是更贵 —— 花得起，且任务确实需要，才用。
```

#### 易错点（25 条摘录）

1. **`drop_duplicates` 必须在 `set_index` 之前**；之后再做，重复时刻已进索引。
2. **异常阈值必须按小时分组**。全局中位数 ×3 会把工业台区（B）的整段日间平台误杀。
3. **哨兵 `9999` 不会自己暴露**。若偷懒只判负值，它就留下了 —— 它占了 7 个越界点里的 1 个。
4. **插值要 `limit_direction="both"`**。默认只向后插，序列**开头**的缺失补不掉（温度有 15 个）。
5. **滑窗必须先 `shift(1)`**；`rolling` 默认右对齐且含当前点。
6. **`rolling(n)` 默认 `min_periods=n`**。最长窗口 168 → 表头 168 行全 NaN，`8592 = 8760 − 168`。
7. **`sd` 的 `ddof` 要对齐**：`pandas.rolling().std()` 是 `ddof=1`，`np.std` 默认 `ddof=0`。
8. **周期整数必须 sin/cos 编码**。23 点与 0 点的整数距离是 23，编码后弦长只有 0.261052。
9. **温度要转成「离舒适区的距离」**。线性相关 −0.19 → `|T−22|` 相关 +0.41。
10. **日周期不一定是正确基线**。有强周周期时先比 `lag168`；B 台区上两者差 **4.16 倍**。
11. **别乱加修正项**。「周周期 × 水平比」实测把基线搅浑（19.1805 → 21.6910）。
12. **时序只能按时间切**；随机切分让 MAE 虚降且完全不报错。
13. **标准化参数只能来自训练段**（Ridge 那一步）。
14. **树模型不需要标准化**，Ridge 必须 —— 两条路线各自的预处理不要混。
15. **`pd.concat` 拼表前先查列重名**。重名会让 LightGBM 抛
    `Feature (h_sin) appears more than one time`（所以目标日历列加 `tgt_` 前缀）。
16. **直接法的训练样本要卡 `tr_pos + h <= tr_pos[-1]`**。越界即泄答，且不报错。
17. **多步评估要先统一「发布口径」**。每天 0 点发布（70 天）与逐小时发布（1695 点）的 MAE 不可比。
18. **递归法的历史必须含原点本身**（`yv[:p+1]`）。写成 `yv[:p]` 整体晚一格，MAE 13.11 → **21.15**。
19. **递归的误差累积在 `h ≤ 最长滞后` 时可忽略**。horizon 24 / 最长滞后 168 ⇒ 累积只有 **0.0138 kW**。
20. **比"哪个模型好"更该问"哪个环节好"**。这里 **3.01 kW** 来自特征对齐，只有 **0.0138 kW** 来自累积。
21. **误差要看它藏在哪个时段**。A 台区晚峰最难（16.7882），B 台区日间最难（21.7747）—— 完全相反。
22. **残差 ACF(24) 为负是"过冲"，为正才是"漏抓"**；两者修法相反（加平滑 vs 加特征）。
23. **神经网络输入必须归一化**。不归一化时 loss 几乎不降，MAE 409.76 vs 17.47，差 **23.5 倍**。
24. **归一化救不了小样本**。LSTM 17.47 → 19.22（越调越差），仍然输给 LightGBM 的 12.67。
25. **报告里的数字必须来自变量**。手打的结论迟早和代码脱节；用 `assert` 把它钉住。

#### 核心结论（可背）

| 场景 | 规则 |
|---|---|
| 基线选哪个 | 有强周周期就**先试 `lag168`**；`lag24` 只是默认值，不是正确答案 |
| 多步用直接还是递归 | 看 **horizon 是否越过最长滞后**：没越过 → 递归（1 个模型、累积≈0）；越过了 → 直接法 |
| 加不加特征 | 先看**残差 ACF 的符号**：正 → 漏抓（加特征）；负 → 过冲（加平滑） |
| 小样本上不上网络 | 先把手写特征 + GBDT 做到位；1 年 × 单台区 × 小时级的规模上，特征工程赢 |

**三组关键数字**：最好基线/最好单步模型 = 19.1805/**12.6689**（特征工程 +34%）；
日前 24 步 = 16.1107（直接）/ **13.1118**（递归）/ 21.6100（基线）；
特征对齐 **3.0127** vs 误差累积 0.0138。

#### 环境坑（本机实测，已登记 `docs/环境依赖.md`）

`lightgbm`（`libomp`）与 `torch`（`libiomp`）各带一套 OpenMP，同进程开多线程会互相踩内存，
直接 **SIGSEGV**（`try/except` 抓不住、报错也看不到）。修法：在**任何 import 之前**
`os.environ["OMP_NUM_THREADS"] = "1"`，并把 LightGBM 的 `n_jobs` 设为 1。

**收尾**：`05_timeseries` 到此全部完成（9 / 9）。把这套流程套到真实赛题数据上时，
优先复查 **特征口径** 与 **多步口径** —— 这两处出错都不会报错，只会让分数虚高或虚低。
