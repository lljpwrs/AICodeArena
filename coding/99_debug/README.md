# 99_debug —— 改错题（debug 型练习）

> 前面的 `01`~`05` 教你「**怎么写出正确代码**」；这一章练的是「**代码错了你能不能看出来**」。

---

## 一、为什么单独开一章

竞赛现场最常见的失分，不是「不会写」，而是这三种：

| 场景 | 练习卷的 `assert` 能拦吗 |
|---|---|
| 知道要用 IQR，但忘了先把哨兵值 9999 剥离 | ❌ |
| 代码跑得通、指标还很好看，其实数据泄漏了 | ❌ |
| 特征列名重复，一路跑到建模才报错 | ❌ |

共同点是：**它不报错**。而练习卷的 `assert` 只验证「你填的那一行对不对」——
可你填的那一行，语法完全正确、逻辑完全错误。

所以需要另一种题型：**给你一段能跑的错代码**。

---

## 二、三道题

| 文件 | 方向 | 四个考点 |
|---|---|---|
| `dbg01_pandas_traps` | pandas | 链式赋值静默失效 / `sort_values` 丢返回值 / 分组聚合写成 `transform` / `astype` 遇脏字符串 |
| `dbg02_sklearn_leak` | 机器学习 | 划分前标准化 / 全量 fit 编码器 / 测试集误用 `fit_transform` / 时序随机切分 |
| `dbg03_timeseries_pitfalls` | 时序 | `rolling` 忘 `shift` / 递归 off-by-one / 直接法列名重名 / `bfill` 借了未来 |

共 **12 题**。每题的「错误代码」都**实跑确认过现象**——要么报错、要么静默出错，
不许凭想象编一个 bug。

---

## 三、怎么用

1. 打开题卷，**先跑一遍**错误代码，观察真实输出——**不要凭直觉猜哪里错**。
2. 用一句话说出「错在哪、为什么」。
3. 改到 `assert` 通过。
4. 对照答案卷。

> **判据：能一句话说清「为什么」，比改对更重要。**
> 竞赛时没人会告诉你错了，只有指标不对劲。

---

## 四、修改与扩展指引

### 加一道新题

1. 打开对应方向的 authoring 脚本（如 `scripts/authoring/dbg01_pandas_traps.py`）。
2. 在 `TASKS` 列表末尾追加一个四元组：`(标题, 题面, 错误代码, 修复代码)`。
3. **先单独跑一遍「错误代码」，确认它的真实现象**，再把现象写进题面。
4. 重跑脚本 + 校验：

```bash
/Users/luolinjie/miniconda3/envs/self/bin/python scripts/authoring/dbg01_pandas_traps.py
/Users/luolinjie/miniconda3/envs/self/bin/python scripts/check_notebooks.py coding/99_debug
```

5. 修复代码里必须带 `assert` —— 答案卷要能全量跑通。

### 约定

| 约定 | 原因 |
|---|---|
| 「错误代码」只出现在**题目卷** | 它真的会抛异常，放进答案卷会让答案卷跑不通 |
| 每题必带「为什么」注释 | 说清原理比改对更值钱 |
| 题面必须写明**真实现象**（打印了什么、值是多少） | 引导「先跑再看」，而不是猜 |
| 新增方向另开脚本 `dbgNN_<方向>.py` | 与 `01`~`05` 的「一章一脚本」约定一致 |

### 生成器

共享生成器是 `scripts/authoring/_debug_core.py` 的 `build_debug()`。
它产出两件套（题目卷 + 答案卷），**不是**挖空三件套——所以
`scripts/check_notebooks.py` 的「练习/答案配对校验」会跳过 `99_debug`
（见该脚本的 `SKIP_PAIR_DIRS`），但仍会做结构校验与逐 cell 语法校验。
