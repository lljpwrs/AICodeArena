# 合成数据规范

> 原则：**数据里必须埋坑**。干净数据练不出竞赛能力——竞赛给的数据一定是脏的，
> 而且「数据探索 + 数据清洗」在评分表里是独立计分项。

---

## 一、基本约定

| 项 | 规定 |
|---|---|
| 位置 | `coding/<方向>/data/make_data.py` |
| 随机种子 | `np.random.seed(42)`，**必须固定**，保证可复现 |
| 运行方式 | `/Users/luolinjie/miniconda3/envs/self/bin/python data/make_data.py` |
| 输出 | 同目录下 CSV（小数据 < 1 MB 直接提交；大数据加进 `.gitignore`） |
| 网络 | **禁止依赖网络**，断网必须能跑通 |
| 幂等 | 重复运行结果完全一致（覆盖写入，不追加） |

---

## 二、命名：一律虚构

台区 / 线路 / 站点 / 设备编号**必须用纯虚构编号**，格式统一为：

```
台区编号    STATION_A_01 ~ STATION_F_06
线路名称    LINE_ALPHA_1 ~ LINE_ZETA_3
设备编号    设备类型缩写 + 3 位序号，如 TR_001（变压器）、CB_002（断路器）
供电所      BRANCH_01 ~ BRANCH_05
```

**禁止**出现任何看起来像真实电网实体的命名（真实地名 + 站名 + 调度编号组合）。即使是编的，观感上也不该像真实数据。

## 三、字段与业务语义

### 主表 `device_defects.csv`（设备缺陷记录，pandas 各章共用）

| 列名 | 类型 | 说明 |
|---|---|---|
| 记录ID | int | 唯一 |
| 台区编号 | str | `STATION_*` |
| 线路名称 | str | `LINE_*` |
| 设备类型 | str | 变压器 / 断路器 / 绝缘子 / 避雷器 / 互感器 |
| 设备编号 | str | `TR_001` 等 |
| 缺陷类型 | str | 渗漏油 / 锈蚀 / 破损 / 发热 / 异物 / 放电痕迹 |
| 缺陷等级 | str | 一般 / 严重 / 危急 |
| 发现日期 | str | **格式故意不统一** |
| 负荷值 | float | **含缺失 + 异常** |
| 温度 | float | **含缺失（MAR）** |
| 湿度 | float | 相对干净，做对照组 |
| 处理状态 | str | **取值故意不一致** |

### 附表（供 `merge` / `join` 章节用）

- `device_info.csv`：设备台账——台区编号、所属供电所、容量kVA、投运年份、供电区域类型
- `station_summary.csv`：台区汇总——台区编号、户数、日均负荷
- `load_curve.csv`：台区负荷曲线——时间戳、台区编号、负荷值、温度（用于 `resample` / `rolling`）

## 四、必须注入的脏数据（每种都给足样本）

### 1. 缺失值

| 类型 | 做法 | 教学价值 |
|---|---|---|
| MCAR | `负荷值` 随机挖 8% | 用均值/中位数填充合理 |
| MAR | `温度` 在 `STATION_C_*`、`STATION_D_*` 上挖掉 25% | 填充策略要分组，不能全局填 |
| 整列高缺失 | 某列缺失 > 70% | 练"该不该删列"的判断 |
| 连续段缺失 | 某台区连续 6 个小时的数据缺失 | 练"单点缺失用均值、连续缺失用同期值" |

### 2. 重复值

- 6 行**完全重复**（所有列相同）
- 4 行**仅记录ID不同**（业务上重复，需要按业务键去重）
- 目的：练 `duplicated()` 默认比全部列 vs `duplicated(subset=[...])` 的区别

### 3. 异常值

| 类型 | 做法 |
|---|---|
| 哨兵值 | `负荷值` 中若干 9999 / -1 |
| 物理越界 | `湿度` 出现 150（>100）、负值 |
| 统计离群 | 3σ 之外的尖峰，用箱线图能看出来 |
| 量纲错乱 | 个别 `负荷值` 是「12.5 kW」字符串 |

### 4. 类型错乱

`负荷值` 列混入：`"N/A"`、`"—"`、`""`、`"12.5 kW"`、`"1,234.5"`
→ 练 `pd.to_numeric(errors="coerce")` + `str.replace` 组合清洗

### 5. 格式不一致

`发现日期` 至少含 4 种格式：

```
2026-03-05
2026/03/05
03/05/2026
2026年3月5日      ← pandas 3.0 的 to_datetime 解析不了，必须手写清洗
```

`缺陷类型` 同一含义多种写法：

```
渗漏油 / 渗油 / 漏油
异物 / 异物搭挂
```

`处理状态` 取值不一致：

```
已处理 / 已 处理 / 处理完成 / done / 处理
```
