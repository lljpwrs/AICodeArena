# 挖空题编写规范

配套文件：`*_practice.ipynb`（练习）与 `*_solution.ipynb`（答案）。

> **不要手写 `*_practice.ipynb`。** 它由 [`scripts/nb_builder.py`](../scripts/nb_builder.py)
> 从 `*_solution.ipynb` 自动派生，Cell 数量 / 顺序 / Markdown / `assert` 在构造上就不可能不一致。
> 你要写的只是 `scripts/authoring/chNN_*.py` 里的源文件。

---

## 一、核心原则

**练习版是答案版的"挖空投影"，不是另写一份。**

| 要求 | 说明 |
|---|---|
| Cell 数量相同 | 一一对应 |
| Cell 顺序相同 | 一一对应 |
| Markdown 内容相同 | 题目描述、提示、小节标题完全一致 |
| Code 中非挖空部分相同 | `import`、数据加载、函数签名、`assert`、绘图收尾 |
| **唯一差异** | 核心代码被替换为挖空占位 |

这样做的目的：练习时你能看到完整的上下文和验收标准，只有"真正要你写的那一两行"是空的。

---

## 二、在源文件里怎么写（DSL）

在普通 Python 代码里插三个指令注释即可：

```python
q1, q3 = df["负荷值"].quantile([0.25, 0.75])      # @@todo 块外的行：两版都保留
iqr = q3 - q1
# @@todo(4) 用 IQR 法算出上下界，把超出范围的值截断到边界上
# @@hint Series.clip(lower=..., upper=...)
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr
df["负荷值"] = df["负荷值"].clip(lower, upper)
# @@end

# ---- 验收 ----
assert df["负荷值"].max() <= upper + 1e-9
```

生成的练习版：

```python
q1, q3 = df["负荷值"].quantile([0.25, 0.75])
iqr = q3 - q1
# TODO(4)：用 IQR 法算出上下界，把超出范围的值截断到边界上
# 提示：Series.clip(lower=..., upper=...)
lower, upper = ____
df["负荷值"] = ____

# ---- 验收 ----
assert df["负荷值"].max() <= upper + 1e-9
```

规则：

| 项 | 约束 |
|---|---|
| `# @@todo(描述)` | 开启挖空块，**必须带描述**，`@@end` 结束 |
| `# @@hint 提示` | 可选，必须紧跟 `@@todo` 之后；**可连续写多条**，依次渲染成多行 `# 提示：` |
| 块内代码 | 所有非注释行被挖空；块内**注释原样保留** |
| 赋值目标 | 自动保留：`x = f(...)` → `x = ____`；`df["c"] = g(...)` → `df["c"] = ____`|
| 无赋值 | 裸表达式 / `plt.show()` → 整行变成 `____` |
| 题号 | `TODO(n)` 自动编号，**不要手写编号** |
| `assert` | **必须写在 `@@end` 之后**，否则会被挖掉导致两版不一致 |
| 控制流 | 块内**不得**出现 `for` / `if` / `def` / `with` / `assert`，生成时直接抛 `BuildError` |

### 两条实现层硬规则（生成器已强制）

**① 按「逻辑语句」挖空，不按物理行。**

跨行表达式只产出一个占位：

```python
# 源文件
# @@todo(10) 组装 report 字典
report = {
    "n_rows": dev.shape[0],
    "n_cols": dev.shape[1],
}
# @@end
```
```python
# 生成的练习版（正确）
report = ____
```

若按物理行挖空，会产出 `report = ____` + 一堆**孤立缩进行** → `IndentationError`。

**② 关键字参数不会被误判成赋值目标。**

```python
df.to_csv(path, index=False, encoding="utf-8-sig", na_rep="NULL")
```
→ 整体变成 `____`，**不会**产出 `df.to_csv(path, index = ____` 这种语法错误。

（实现上：用 `tokenize` 只在**括号深度 0**的第一个 `=` 处切分，不是用正则。）

**③ 块内嵌在 `for` / `if` 里也照样能按逻辑语句分组。**

挖空块常常「循环骨架外置、`@@todo` 放循环体内」，此时整块都是缩进状态。
生成器会**先 `textwrap.dedent` 再 `ast.parse`**，所以缩进块里的跨行语句
同样只产出一个占位：

```python
# 源文件（块体整体缩进 4 格）
for key, val in cfg:
    # @@todo 组装并落表
    table[(key, val)] = (round(float(h.max()), 6),
                         int((h > 0.01 * h.max()).sum()))
    # @@end
```
```python
# 生成的练习版（正确：一个占位，不是两个）
for key, val in cfg:
    # TODO(1)：组装并落表
    table[(key, val)] = ____
```

> 历史坑：早期版本直接 `ast.parse` 未 dedent，缩进块必然解析失败、
> 退回「逐行挖空」，于是跨行语句被拆成 `table[...] = ____` + 一行孤立缩进的
> `____` → `IndentationError`。已在 `nb_builder._statement_spans` 修掉。

**结论：源文件里可以放心写多行语句，不必为了迁就挖空而压成一行 ——
无论挖空块是否缩进。**

## 三、挖空量与难度递进

| 题号 | 定位 | 挖空数量 |
|---|---|---|
| TODO(1) | 单方法直用 | 1~2 行 |
| TODO(2)~(n-2) | 方法组合、参数选择 | 2~3 行 |
| TODO(n-1) | 易错场景（缺失、类型、边界） | 3~5 行 |
| TODO(n) / 综合题 | **跨小节组合题** | 允许 5~8 行，可分多步 |

**不要这样做**：

```python
# ❌ 挖太多，整段变成默写比赛
____
____
____
____

# ❌ 没有提示，只能靠猜
result = ____

# ❌ 把装饰性调用也挖掉（set_title / tight_layout / show 留在块外即可）
fig, ax = ____
boxes = ____
____
____
____
____
```

## 四、必须保留 `assert` 验收块

每题末尾保留可运行的验收代码，让练习者**自己就能判断对错**，不用翻答案：

```python
# ---- 验收 ----
assert result is not None, "result 不能为空"
assert result.index.name == "设备类型", "分组键应为设备类型"
assert abs(result.sum() - 1234.5) < 0.1, "总和不符，检查是否漏掉了某些设备"
```

要求：

- 断言信息写**检查什么**，不写**答案是什么**
- 用 `abs(x - y) < eps` 代替 `x == y` 比较浮点
- **断开言真值必须来自真实运行结果**，且与方向 README 的「真值备忘」表对得上
- 图表题断言"图对象已生成"，并顺带断言组数 / 柱数：

```python
assert len(boxes["boxes"]) == 5, f"应有 5 个箱体，实际 {len(boxes['boxes'])}"
```

- 避免"某组一定没有离群点"这类假设 —— 空数组上 `.max()` 会 `ValueError`。
  稳妥写法：
  ```python
  flier_max = max((float(f.get_ydata().max()) if len(f.get_ydata()) else 0.0)
                  for f in boxes["fliers"])
  ```
