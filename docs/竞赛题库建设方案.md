## 1. 竞赛考点研究结论

### 1.1 三条主要赛道

**A. 中电联「电力行业职业技能竞赛」**（最对口，评分细则最细）

- 2025 年首届「人工智能训练师」：理论考计算机原理 / 数据结构 / 算法；**技能操作只有两大项——「电力现场作业安全监督场景综合应用」+「大语言模型特定任务微调」**。
- 2026 年「生成式人工智能系统应用员 S」：理论覆盖数据处理、机器学习与深度学习、模型训练与优化、生成式 AI 系统设计；技能操作考**生成式模型微调与对齐 / RAG / Agent**。
- 规模参考：2026 年 51 支队伍、153 名选手；赛期 2 天。

**B. 国家电网公司级竞赛**

- 2025 年「大数据应用和大模型应用技能竞赛」：两个方向，含**团体赛 + 个人理论竞赛 + 个人实操竞赛**三个环节。
- 团体赛主题示例：配电网停电原因分析、供电方案自动生成。
- 个人赛强调"大数据与大模型的全链路实践操作与问题解决能力"。

**C. 算法打榜类（数字中国创新大赛·能源大数据创新应用赛）**

- 连续五届由国网福建电力承办；算法赛题示例：**基于时序大模型的新能源微观气象要素与功率预测**、基于多源数据融合的电动汽车充电站协同优化。
- 2026 年超 5400 支队伍报名，纯线上提交 + 榜单排名。

### 1.2 技能操作的评分结构（关键情报）

**江苏选拔赛（第八届全国职工职业技能大赛人工智能训练师赛项）** —— 实操 480 分钟 / 3 道题 / 350 分：

| 模块 | 时长 | 分值 | 拆解 |
|---|---|---|---|
| A 数据分析与挖掘 | 90 min | 50 | 第一步数据探索 20 分（3 项探索 + 5 项清洗 + 2 项可视化，每项 2 分）；第二步数据挖掘 20 分（5 项任务，每项 4 分）；第三步模型评估调优 10 分 |
| B 大语言模型特定任务微调 | 180 min | 100 | 提供 2B 级模型 + 3 种下游任务数据集，做 PEFT |
| C 智能自动驾驶场景综合应用 | 210 min | 100 | 场景综合 |

**某市 2026 人工智能训练师竞赛技术文件** —— 技能操作权重：

```
数据准备及处理 10% ｜ 模型选择 10% ｜ 模型训练 40%
模型调参 10% ｜ 模型性能评估 10% ｜ 技术文档撰写 20%
```

**国家职业技能标准（三级）** 操作技能考核要素：业务分析 → 智能训练（数据处理规范制定 + 算法测试）→ 智能系统设计。评分细目精确到"用箱线图检测异常值得 1 分""用 IQR 处理异常值得 1 分""回答数据清洗规范，每答对 1 个规范点得 1 分，最高 3 分"。

### 1.3 对本题库的三条直接推论

1. **"按步骤给分"意味着流程完整性比精度更重要。** 练习必须能自查"我漏了哪一步"，而不是只对最终分数。→ 决定 §5 的"验收断言"机制。
2. **数据探索 + 数据清洗 + 数据可视化是独立计分项，各 2 分。** 这三类操作要被拆成原子级考点反复练，而不是塞在综合题里一带而过。→ 决定 §4.1 的 pandas 章节粒度。
3. **技能操作是 Jupyter 上机、限时、可能断网。** 复习时就要模拟这个约束。→ 决定 §5 的限时训练与 §6 的环境规范。

## 3. 章节文件的三段式规范

### 3.1 讲解 notebook（`chXX_*.ipynb`）

统一结构：

1. **本节考点**（Markdown cell）：对应竞赛的哪个评分点，标注分值含义
2. **API 速查表**：方法名 / 参数 / 返回值 / 一句话说明
3. **最小示例**：用 3~5 行数据演示单个方法
4. **组合示例**：多个方法链式使用
5. **易错点**：常见报错、返回视图还是副本、`inplace` 陷阱、类型陷阱
6. **小结**：一句话记住这个方法的判断标准

### 3.2 练习 notebook（`chXX_*_practice.ipynb`）

挖空规则：

- **保留**：题目描述、注释、函数签名、数据加载、`import`、`assert` 验收代码、绘图收尾
- **挖空**：核心 API 调用、参数选择、链式操作

统一挖空格式：

```python
# TODO(3)：按「设备类型」分组，计算每组「缺陷数」的均值，结果存入 result
# 提示：使用 DataFrame.groupby(...).agg(...)
result = ____
```

### 3.3 答案 notebook（`chXX_*_solution.ipynb`）

- 与练习 notebook **Cell 数量、顺序、标题完全一致**
- **完整可直接运行**（`Run All` 无报错）
- 关键步骤后附一行 Markdown 说明"为什么这样做"

### 3.4 一致性约束（硬性）

| 约束 | 检查方式 |
|---|---|
| 练习 / 答案 Cell 数一致 | `scripts/check_practices.py` |
| 所有 solution `Run All` 通过 | `scripts/check_solutions.py` |
| 所有 practice 在挖空处必然报错 | `scripts/check_practices.py` |
| 不使用绝对路径 | 全局 grep |

### 6.1 Python 环境（沿用既有约定）

- 固定使用 `/Users/luolinjie/miniconda3/envs/self/bin/python`
- **不新建 venv**，缺包直接 `pip install` 到该环境，用完不卸载
- 依赖清单记录在 `docs/环境依赖.md`（不是靠 venv 隔离）

### 6.2 Notebook 规范

- 不使用绝对路径，统一 `pathlib.Path(__file__)` 或相对 `./data/`
- 单元格输出：建议接入 `nbstripout` 到 pre-commit，避免仓库膨胀
- 代码行长 ≤ 100（与既有 ruff 配置一致）
- 中文字体统一配置（`plt.rcParams['font.sans-serif']`），避免绘图乱码

### 6.3 合成数据规范

- 每章 `data/make_data.py`，固定 `np.random.seed(42)`
- 字段名贴近电力业务：`台区编号` / `线路名称` / `设备类型` / `负荷值` / `温度` / `湿度` / `缺陷类型` / `缺陷等级`
- 必须**人为注入**：缺失值（MCAR / MAR 各若干）、重复行、异常值、类型错乱、不一致格式
- 小数据（< 1 MB）直接提交 CSV；大数据只提交脚本，CSV 加 `.gitignore`

### 6.4 Git 规范

- 一章一 commit，信息格式：`feat(pandas): add ch04 缺失值处理`
- 提交前跑 `pre-commit run --all-files`
- 不提交 `.workbuddy/`（已在 `.gitignore`，但被保护，勿删）

### 6.5 自动化校验脚本

| 脚本 | 职责 |
|---|---|
| `scripts/check_solutions.py` | 用 `nbconvert --execute` 跑通所有 `*_solution.ipynb` |
| `scripts/check_practices.py` | 校验：① 与对应 solution 的 Cell 数 / 标题一致；② 挖空版必然执行失败 |
