# exams/ —— 限时全真模拟卷

严格计时，做完再用**可执行评分表**逐项核对。**这是本仓库区别于普通教程的核心价值**——竞赛按步骤给分，练的就是"不漏步"。

> 与 `coding/` 的区别：`coding/` 是「按知识点练」，`exams/` 是「按考场练」——
> 不给提示、不给小标题、限时、且**做完有东西告诉你漏了哪一步**。

## 五、判卷器（本仓库的关键工具）

`exams/README.md` 原来的评分表是**静态 Markdown，靠你自己打勾**——而自己给自己打分最不可靠。
现在改成**可执行**的：

```bash
# 完整判卷（执行 notebook，抓 stdout、命名空间、绘图调用）
/Users/luolinjie/miniconda3/envs/self/bin/python scripts/grade_notebook.py \
    "exams/mock01_数据分析与挖掘/mock01.ipynb"

# 只做静态检查（不执行，秒出结果）
... --static-only

# 输出机器可读结果
... --json
```

判卷器**双通道**工作：

| 通道 | 看什么 | 能抓什么 |
|---|---|---|
| **静态**（AST / 文本扫描） | 你**写了什么** | 该调的 API 调没调、顺序对不对（如「先划分再标准化」） |
| **动态**（执行 + 埋点） | 结果**对不对** | stdout 里的关键数字、变量是否存在、图画没画 |

实测效果：

| 场景 | 得分 | 说明 |
|---|---|---|
| 答案卷 | **50 / 50** | 18 项全过 |
| 空白卷 | **0 / 50** | 18 项全部标出 |
| 故意漏做 V1 / V2 / T2 | **42 / 50** | **失分项精确命中** |

> 判卷器判的是**「步骤是否完整」**，不判「代码写得好不好」。
> 一个步骤用一行还是一行写完，不影响计分 —— 这正是「按步骤给分」的复核方式。

## 六、使用纪律

1. **先计时再开始**，中途不看答案、不查文档（模拟断网）
2. 时间到就停手，即使没做完
3. 用 `rubric.yaml` 跑判卷器，**逐项看**哪一步没做、为什么没通过
4. 把失分项写进 [`../_notes/错题本.md`](../_notes/错题本.md)
5. **一周后重做卷子**，目标是把漏掉的步骤全补上
